# CLAUDE.md — JewelryLearning 开发规范

> 本文件是这个仓库的开发约定，Claude Code 会自动加载。人类或 AI 在此仓库开发时**必须遵守**。
> 目的：让这本《珠宝入门：从宝石学原理到不被坑》保持统一、正确、可移植。
> 体例继承姊妹项目 InfraLearning / MultiModalLearning / TeaLearning。

## 1. 这是什么

一本"边学边记"的珠宝入门书，**双目标**：

1. **实用**：选购不被坑（会看名称、会看证书、会识别处理与合成、会判断哪些参数值得花钱）；
2. **系统**：深度对标 **GIA GG / FGA / NGTC 的宝石学知识体系**（晶体学、光学、成因、鉴定、分级）。

面向零基础但要求讲透原理的读者。品类**全覆盖均衡**：钻石 / 有色宝石 / 玉石 / 有机宝石 / 贵金属工艺。
最终会成书，所以：

> **⚠️ 内容必须非常正确。**

姊妹书 InfraLearning 靠"真机跑数据"保证正确性；珠宝没有 GPU 可跑，**本书的正确性靠四条纪律**：

1. **数值必须有出处**：折射率、比重、硬度、分级边界、含量限值等，一律标注来源
   （国标编号 / GIA·FGA 教材 / 权威实验室 / 明确标注为"行业经验值"），并给**区间**而非单点。
   **禁止凭印象编造精确数字**——宁可写"典型在 x~y，因产地/成分而异"。
2. **区分「事实」「标准规定」「市场惯例」「传说」**四层：
   - **事实**：物理化学性质，可验证；
   - **标准规定**：国标/CIBJO/实验室规则怎么写的（引标准号）；
   - **市场惯例**：行业怎么叫、怎么定价（明说是惯例，可能变）；
   - **传说**：珠宝圈流传的说法。凡证据不足的，写进「常见说法辨析」小节，
     标注**证据强度**（有共识 / 有争议 / 缺乏证据 / 明确错误），不含糊其辞。
3. **价格只讲机制，不写死数字**：金价、钻石价、翡翠价随时变。正文写**定价逻辑与相对关系**
   （"某参数每降一级约让价 x%"这类**结构**），需要绝对数字时标注"截至 YYYY-MM 的量级，仅供理解结构"。
4. **不做投资建议、不做鉴定结论**：本书教怎么看、怎么问、怎么送检；
   明确写"隔着屏幕不能下鉴定结论"，贵重件一律建议**权威实验室复检**。

**法律合规**：涉及象牙、犀角、玳瑁、部分珊瑚等受 CITES 及国内法管制的材料，只讲识别与法律风险，
**不提供任何交易渠道信息**。

### 1.1 查证纪律（硬要求，写每一章都适用）

> **不要凭记忆写作。** 姊妹书 InfraLearning 有真机数据可跑，珠宝没有——
> **所以"查资料"是本书正确性的唯一来源**，不是可选项。
> 珠宝更是个话术密度极高的行业，模型记忆里混进了大量销售话术与自媒体误传。

1. **写之前先查**：动笔前检索**一手资料**（国标原文与官方解读、GIA / SSEF / Gübelin / AGL /
   NGTC 的公开资料、*Gems & Gemology* 等同行评议文献、权威教材如《系统宝石学》），
   而不是凭印象组织内容。**先列出本章每个数值与每条判据的来源，再开始写**。
2. **一手优先，来源分级**：国标与 CIBJO/LMHC 规则 / 权威实验室发布物 / 同行评议论文 /
   权威教材 > 行业协会与检测机构科普 > 头部专业媒体（如 Lotus Gemology、IGS）>
   珠宝商内容 > 自媒体与直播话术。
   **商家内容与自媒体一律不作依据**，只能当"市场上存在这种说法"的证据（正是辨析小节的素材）。
3. **关键结论交叉验证**：折射率 / 比重 / 硬度 / 双折射、分级边界、处理手段的识别判据、
   清洗禁忌，至少**两个独立来源**一致才写；只有一个来源时明确标注"仅见于 X"。
4. **出处要落盘**：所有引用登记进 `docs/reference/standards.md`（`check_book.py` 会强制
   GB/T 编号必须登记）；物理常数登记进 `docs/reference/constants.md` 并注明来源与波动原因。
5. **查不到就别写**：宁可写"这一点缺乏可靠公开数据"或改成区间描述，
   **绝不用听起来合理的措辞填补空白**。发现自己在"推测"时，停下来去查，或显式标注为推测。
6. **凡话术必辨析**：珠宝圈说法一律进「常见说法辨析」小节，标注证据强度
   （有共识 / 有争议 / 缺乏证据 / 明确错误），并说明它为什么流传、卖家为什么爱说。
7. **警惕自己的记忆**：标准版本与修改单、实验室报告的术语（如充填程度分档）、
   产地判定的当前能力边界、培育钻石的技术与价格现状，**默认记忆已经过期**，一律现查。
8. **国内外规则不一致时并列**：国标的"优化/处理"二分与国际报告的表述方式不同，
   **不要把一方当成唯一正确**——并列说明，指出读者在中国市场与海外市场分别会看到什么。

## 2. 教学法（每章固定结构）

用**中文**写。每章遵循「**概念 → 思考题 → 实操**」：

1. **概念**讲解，配机理图（Mermaid）/ 对照表，关键数值带出处；能讲"为什么"就不要只讲"是什么"；
2. 章末**思考题**（数量**按实际需求，可多可少**），紧扣本章，指向答案册（见 §5）。
   题型混用三种：
   - 普通问答（考原理）；
   - **【案例】判断题**：给一段真实感的商品描述 / 证书信息 / 报价，问"值不值得买、坑在哪"，
     答案册必须给**完整推理链**，而不只是结论；
   - **【辨识】题**：指向 `docs/reference/gallery.md` 里的权威图库，让读者看图找特征。
3. **本章实操**：读者**不一定有宝石和工具**，所以每个实操写成两档：
   - **🅐 无器具版**（看电商详情页 / 看证书 PDF / 查权威图库 / 翻自己首饰盒 / 逛店只用眼和手，随时能做）；
   - **🅑 有器具版**（需要 10 倍放大镜、强光手电、电子秤、查尔斯滤色镜、偏光片等，标注"备齐后再做"，
     列清所需器具与替代方案）。
   实操要给**可填写的记录表**（Markdown 表格或链到 `docs/forms/`），让观察沉淀下来。

风格：像给同事讲清楚一件事，多用"为什么"，诚实标注反直觉/局限（"诚实说明"）。
**绝不写"某某一定是假的"这类隔屏断言**——写"出现这些特征时，怀疑 X，需要 Y 来确认"。

## 3. 单一真源 & 可移植 Markdown（核心原则）

- **内容只存一份**：正文 `docs/`。网页/PDF 都是它的渲染。
- **可移植 Markdown**：必须在 **GitHub 原生渲染 + 普通 Markdown 阅读器 + MkDocs** 三边都能看：
  - 用**脚注 + 引用块**做注释，**不要**用 MkDocs 专有的 `!!! note` admonition；
  - 术语表锚点、思考题跳转都用**显式 HTML 锚点** `<a id="xxx"></a>`（三边通用）；
  - 不用 `--8<--` / `{{#include}}` 这类构建期引用（纯阅读器看不到）。
- **可复用的表单**（观察记录表、证书核对清单、选购决策表等）放 `docs/forms/`，
  各章**链接**过去，不复制粘贴。
- **图片版权**：本书**不搬运**他人实拍照片。需要看实物图时，链到权威图库
  （`docs/reference/gallery.md` 统一登记），正文给**文字判据**（"应该看到什么"）。
  自绘示意图用 Mermaid 或 matplotlib。

## 4. 目录结构与命名

```
docs/                          # 正文（唯一内容真源）
  index.md                     # 封面 / 大纲 / 进度
  roadmap.md                   # 七部分学习路线图（活的大纲，改动记进"调整记录"）
  glossary.md                  # 术语表（中文 + 英文 + 解释，每词条前有 <a id> 锚点）
  reference/                   # 活的速查资料
    standards.md               # 标准与文献索引（所有引用出处集中登记）
    constants.md               # 宝石物理常数速查表（RI / SG / 硬度 / 双折射 / 荧光）
    gallery.md                 # 权威图库索引（看实物图去哪里，看什么）
  forms/                       # 可复用记录表（观察表、证书核对清单、选购决策表…）
  chapters/NN-partname/        # 每部分一个目录
    00-intro.md                # 该部分开篇导读（每部分都要有）
    NN-name.md                 # 章节，两位数字前缀（全书连续编号）
    summary.md                 # 该部分小结（速查）
    project-PN-xxx.md          # 该部分的实战项目（见 §6）
    figures/                   # 该部分的图
  qa/NN-name-qa.md             # 思考题答案册（网页可跳转）
scripts/check_book.py          # 校验：思考题锚点/术语锚点/标准登记/绝对路径/admonition
mkdocs.yml                     # 站点配置
.github/workflows/docs.yml     # GitHub Pages 自动发布（跑 check_book + build --strict）
```

命名对应：第 N 章 → `chapters/PART/NN-name.md`、`qa/NN-name-qa.md`。

## 5. 各类文件的具体约定

**章节 `.md`**：小节用 `## N.x 标题`。术语首次出现加脚注 `[^x]`，脚注体链接到术语表
`[术语](../../glossary.md#anchor)`。章末思考题下写跳转链接：
`> 📖 **参考答案**（想清楚再看）：[Q1](../../qa/NN-name-qa.md#q1) · [Q2](...#q2) · …`

**答案册 `docs/qa/NN-name-qa.md`**：**只记「问题 + 正确答案」**，不记读者作答。每题前加锚点
`<a id="q1"></a>`…。案例题答案要给推理链（"看到什么 → 推出什么 → 还需要确认什么"）。
必须加进 `mkdocs.yml` 的「思考题参考答案」nav（否则 `--strict` 报错）。

**出处标注格式**：正文引用标准写 `GB/T 16552`（**不带年份**，避免版本漂移误导），
在 `docs/reference/standards.md` 里登记完整名称、当前版本与要点，并注明"以最新发布版本为准"。
教材引用统一简称（如《系统宝石学》《GIA 彩色宝石课程》），同样在 `standards.md` 登记。
行业惯例写明"**市场惯例**，可能随行情变化"。

**术语表**：新术语加到 `glossary.md` 对应主题下，前置 `<a id="slug"></a>`。
珠宝术语要给 **中文 + 国标术语原词（若有）+ 英文**——因为证书多是英文，读者必须能对上。

## 6. 实战项目（重要：不要一章一个）

- 项目**只挂在部分末尾或关键节点**，同一部分**最多一个**，全书 **5 个**（P1~P5）。
- 项目文档放**所属部分目录**里（`chapters/NN-part/project-PN-xxx.md`），
  nav 排在该部分末尾，**不单独设分区**。
- 项目同样给「🅐 无器具版 / 🅑 有器具版」两档，并给交付物模板（表格 / 决策清单）。

## 7. 画图（Mermaid 优先）

> **随时画图**：只要图比文字更清楚，就配图——这是硬要求，别偷懒用纯文字凑。

- **分类树 / 判定流程 / 光路 / 工艺流程 / 决策树 → Mermaid**：```mermaid 代码块，三边都渲染、可 diff。
  本书最常用：珠宝玉石分类树、国标定名判定流程、鉴定流程图、4C 权衡决策树、处理手段识别路径。
- **数据图表 → matplotlib PNG**：**只在有可靠数据来源时才画**，图注必须写来源；
  没有来源就不要画成"像实测数据"的图，改用示意图并在标题里写明"示意"。
  规范：Okabe-Ito 色盲安全配色（`#0072B2 #E69F00 #D55E00 #009E73 #56B4E9 #CC79A7`）、白底、
  英文标签（避免 matplotlib 缺中文字体出方框）、细线淡网格、**不要双 Y 轴**；生成后打开图看一眼。
- **颜色描述**：涉及宝石颜色的图/表，不要只靠色块传达信息（色盲不友好且屏幕色差大），
  必须同时给**文字描述**（色调 hue / 饱和度 saturation / 明度 tone 三要素）。

## 8. 新增一章的标准流程（照做）

1. 先列本章的知识链条，确认每个数值有出处（查不到就改写法，别编）；
2. 写 `docs/chapters/PART/NN-name.md`（概念 + Mermaid/表 + 常见说法辨析 + 思考题 + 实操 🅐/🅑）；
3. 写 `docs/qa/NN-name-qa.md`（问题 + 正确答案，q1/q2/… 锚点；案例题给推理链）；
4. 新术语加进 `glossary.md`，新出处加进 `reference/standards.md`，新常数加进 `reference/constants.md`，
   新图库加进 `reference/gallery.md`；
5. 更新 `mkdocs.yml`（章节 nav + 答案 nav）、`docs/index.md`（进度）、`docs/roadmap.md`（状态）；
6. **校验 + 严格构建**（见 §9）全绿后再提交。

## 9. 构建与校验（提交前必做）

```bash
python scripts/check_book.py     # 锚点/标准登记/绝对路径/admonition/图片版权检查
mkdocs build --strict            # 坏链接/警告即失败（CI 也跑这条）
```

两条全过才提交。`--strict` 失败会导致 GitHub Actions 部署失败、网页冻结——务必本地先过。

## 10. 提交与发布

- 提交信息中文、说清做了什么 + 为什么；**每完成一块可独立成立的内容就提交**，不要攒到最后。
- push 到 `main` 触发 Actions 自动构建并发布到 GitHub Pages。
- `mkdocs.yml` 配 `site_url` + `repo_url` + `repo_name`；`README.md` 顶部放**在线阅读**链接——
  网页与仓库互相可达。

## 11. 通用约束（来自用户全局规范）

- **不主动写报告文件**（`*.md` 总结、`report_*.json` 等）；结论直接说，除非明确要求导出。
- 需要时间戳用**北京时间**：`TZ='Asia/Shanghai' date '+%Y-%m-%d %H:%M'`。
- **仓库内所有文件禁止出现绝对路径**（尤其带用户名或机器目录布局的）——公开仓库会泄漏个人信息；
  只用相对路径 / 环境变量。聊天里为方便定位可给绝对路径，但**绝不提交进仓库**。
