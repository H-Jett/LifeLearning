# 🛠 项目 P5：写出你自己的配方手册

> **这是全书的验收。**
> 交付物不是一叠收藏配方，而是至少三款你能复做、比较、诊断的成品卡：每张都能回答比例、角色、参数、结果和下次怎么验证。

## P5.1 手册的最小结构

```mermaid
flowchart LR
    A[配方百分比] --> B[角色与四本账]
    B --> C[过程参数与状态]
    C --> D[成品与保存观察]
    D --> E[失败诊断 / 下一次单变量]
    E --> A
```

| 一张成品卡必须有 | 为什么 |
|------------------|--------|
| 面粉总量为 100% 的烘焙百分比 | 能缩放与比较 |
| 原料在本配方中的角色 | 知道改动会牵动谁 |
| 关键过程条件和状态 | 让“照做”变成可复现 |
| 出炉、冷却和保存观察 | 不把不同阶段的问题混在一起 |
| 下一次只验证一个变量 | 保留因果判断 |

## P5.2 🅐 零成本版：完成三张纸上成品卡

从做过或想做的三类成品中各选一款。即使没有烤箱，也能完成前两列；未做过的结果栏写“待验证”，不能填成想象中的结论。

| 成品 | 百分比与基准 | 四本账的判断 | 关键步骤 / 状态 | 成品目标 | 最大不确定性 |
|------|--------------|--------------|-----------------|----------|--------------|
| A | | | | | |
| B | | | | | |
| C | | | | | |

至少让三张卡跨两种结构路径，例如化学膨松、酵母、泡沫、层状结构或无麸质体系；目的不是凑品类，而是训练你不会把一种经验外推到所有成品。

## P5.3 🅑 开火版：把记录变成自己的参数库

为三张成品卡各保存一次完整的[配方解码表](../../forms/recipe-decode.md)和[烘焙记录与复盘表](../../forms/bake-log.md)。一张卡至少有基线或一次明确的单变量比较。

| 成品 | 基线版本 | 我验证的唯一变量 | 预测 → 实际 | 可复用的条件 | 仍待验证 |
|------|----------|------------------|-------------|--------------|----------|
| A | | | | | |
| B | | | | | |
| C | | | | | |

写“可复用”时必须附条件：面粉 / 原料、模具、炉位、环境或设备的哪一项适用。它不是全网通用答案，而是你自己的条件下暂时可信的结论。

## P5.4 让手册可以继续长大

每次新增一款成品，只做四件事：

1. 换算成烘焙百分比；
2. 标出四本账中最紧的那一笔；
3. 记录一个关键状态和一个出炉 / 冷却结果；
4. 若要改，先写预测，只改一个变量。

| 发现 | 手册中应该补什么 |
|------|------------------|
| 同配方换粉后状态变了 | 原料与实际用水记录 |
| 同配方在不同炉位不同 | P3 烤箱地图与炉位备注 |
| 隔日口感变了 | 包装、保存与时点观察 |
| 预测不成立 | 删除旧假设，写下一次最小验证 |

## P5.5 自检清单

| 做到了 | 含义 |
|--------|------|
| 每张卡都写明百分比基准 | 你能比较与缩放 |
| 角色不是只写原料名 | 你能预测替换代价 |
| 有过程状态，而非只有时间 | 你能适配自己的环境 |
| 失败卡也保留 | 你知道边界在哪里 |
| 下一步一次只验证一个变量 | 你的手册会越来越可信 |

## P5.6 🔎 全书之后怎么用

以后遇到新配方，不必先问它“准不准”。先把它翻译进手册：它的比例和你的基线差在哪、它优先照顾哪本账、你的设备能否复现关键条件。然后用一炉小实验，让手册多一条自己的证据。

## P5.7 本项目依据

项目复用第 9 章烘焙百分比、第 26 章称量与记录、第 41～45 章的配平、替换、诊断和保存框架，以及全书的“单变量、先预测后验证”纪律。它不取代任何所在地的食品安全要求；来源与限制见[参考书目与出处登记](../../standards.md)。

**烘焙的原理到此完成。**

你不需要记住所有答案；保留一套能提出问题、记录条件、验证下一步的方法，就能持续把每一炉变成自己的证据。
