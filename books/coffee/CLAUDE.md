# CLAUDE.md — 《系统学咖啡》（books/coffee）开发规范

> ⚠️ **本书是 `H-Jett/LifeLearning` 仓库中的一本**（位于 `books/coffee/`），不是独立仓库。
> 仓库级约定（books.yml、统一构建、提交前缀）见根目录 [`CLAUDE.md`](../../CLAUDE.md)。
> **书内的写作纪律以本文件为准**，仓库级文件不覆盖它。

> 本文件是这本书的开发约定，Claude Code 会自动加载。人类或 AI 在此目录下开发时**必须遵守**。
> 目的：让这本《系统学咖啡：从一颗生豆到一杯咖啡》保持统一、正确、可移植。
> 体例继承姊妹书 TeaLearning / JewelryLearning。

## 1. 这是什么

一本"边学边记"的咖啡入门书，**双目标**：

1. **实用**：会买豆（读懂标签）、会冲煮（知道每个旋钮在调什么分子）、会描述（说得出为什么）；
2. **系统**：深度对标 **SCA / CQI（Q-Grader）的知识框架**——咖啡化学、处理法、烘焙、
   萃取物理、感官审评，讲原理而不是背结论。

面向零基础但要求讲透原理的读者。链条**全覆盖**：种植 / 处理 / 烘焙 / 萃取 / 感官 / 选购。
最终会成书，所以：

> **⚠️ 内容必须非常正确。**

姊妹书 InfraLearning 靠"真机跑数据"保证正确性；咖啡没有 GPU 可跑，
**本书的正确性靠四条纪律**：

1. **数值必须有出处**：成分含量、温度、时间、萃取率、粒径等数字，一律标注来源
   （ISO / SCA / CQI 等标准与协议 / 同行评议论文 / 权威教材），并给**区间**而非单点。
   **禁止凭印象编造精确数字**——宁可写"典型在 x~y，因品种/处理/烘焙差异很大"，
   或者干脆**只写规律不写数字**。
2. **区分「事实」「标准规定」「行业惯例」「圈内说法」**四层：
   - **事实**：物理化学性质与可复现的测量，可验证；
   - **标准规定**：ISO / SCA 协议 / 出口国分级规则怎么写的（引编号）；
   - **行业惯例**：精品咖啡行业怎么做、怎么定价（明说是惯例，会变）；
   - **圈内说法**：咖啡社群与自媒体流传的说法。凡证据不足的，写进「常见说法辨析」小节，
     标注**证据强度**（✅ 有共识 / ⚠️ 有争议 / ❌ 明确错误 / 缺乏证据），不含糊其辞。
3. **价格只讲机制，不写死数字**：生豆 C 价、精品豆零售价、器具价格随时变。正文写**定价逻辑
   与相对关系**（"某一项每提一档大约贵多少倍"这类**结构**），需要绝对数字时标注
   "截至 YYYY-MM 的量级，仅供理解结构"。
4. **不做医疗 / 健康建议**：咖啡与健康**只讲证据等级**（谁做的研究、什么设计、
   哪个机构的结论），**不给摄入量建议、不做疗效或风险承诺**。
   涉及 EFSA / IARC 这类机构结论时，只复述其原话与适用范围。

### 1.1 查证纪律（硬要求，写每一章都适用）

> **不要凭记忆写作。** 姊妹书 InfraLearning 有真机数据可跑，咖啡没有——
> **所以"查资料"是本书正确性的唯一来源**，不是可选项。
> 咖啡更是个"实践经验先行、科学解释后到"的领域：模型记忆里混进了大量
> 器具商文案、咨询师口号与论坛共识，其中一部分是错的，另一部分只是**尚未被验证**。

1. **写之前先查**：动笔前检索**一手资料**（ISO 标准摘要、SCA / CQI / WCR / ICO 官方页面、
   *J. Agric. Food Chem.* 等同行评议文献、权威教材如 *The Craft and Science of Coffee*、
   Illy & Viani *Espresso Coffee: The Science of Quality*），而不是凭印象组织内容。
   **先列出本章每个数值与每条判据的来源，再开始写**。
2. **一手优先，来源分级**：ISO / 标准与协议原文 / 同行评议论文 / 权威教材 >
   SCA·CQI·WCR·ICO 等机构的公开资料 > 有实验的技术型作者与实验室
   （如公开方法与数据的独立研究）> 头部专业媒体 > 器具商与烘焙商内容 > 自媒体与短视频。
   **商家内容与自媒体一律不作依据**，只能当"市场上存在这种说法"的证据
   （正是「常见说法辨析」小节的素材）。
3. **关键结论交叉验证**：成分含量、反应温度、萃取率边界、粒径、水质指标、
   咖啡因含量，至少**两个独立来源**一致才写；只有一个来源时明确标注"仅见于 X"。
4. **出处要落盘**：所有引用登记进 [`docs/standards.md`](docs/standards.md)
   （`check_book.py` 会强制正文出现的 `ISO xxxx` / `GB/T xxxxx` 编号必须登记过）。
5. **查不到就别写**：宁可写"这一点缺乏可靠公开数据"，或改成**规律描述 + 标注"经验值"
   并说明波动范围**，**绝不用听起来合理的措辞填补空白**。
   发现自己在"推测"时，停下来去查，或显式标注为推测。
6. **凡说法必辨析**：咖啡圈说法一律进「常见说法辨析」小节，标注证据强度，
   并说明它**为什么流传**（通常是因为在某个特定场景下确实成立，被过度推广了）。
7. **警惕自己的记忆**：SCA 的协议版本（例如百分制杯测表与新的 Coffee Value Assessment
   并行/替代关系）、ISO 标准的现行版本、品种目录、处理法术语、各国分级规则，
   **默认记忆已经过期**，一律现查。
8. **版权红线**：**不得复制 SCA 官方杯测表 / CVA 表的条文与分值版式**，
   也不得复制风味轮图片——那些是有版权的。本书只能"参考其框架**自拟**"，
   并在正文明确写出这是自拟表、官方表请去官方网站取得。

## 2. 教学法（每章固定结构）

用**中文**写。每章遵循「**概念 → 辨析 → 思考题 → 实操**」，
顺序与小节名固定（`scripts/check_book.py` 会检查）：

1. **概念**讲解，配机理图（Mermaid）/ 对照表，关键数值带出处；
   能讲"为什么"就不要只讲"是什么"；
2. **「常见说法辨析」**表：逐条列出咖啡圈的说法，标注证据强度
   （✅ 有共识 / ⚠️ 有争议 / ❌ 明确错误 / 缺乏证据）并给一句理由；
3. 章末**思考题**（数量**按实际内容而定，不固定 3 道**），紧扣本章，指向答案册（见 §5）。
   题型混用三种：
   - 普通问答（考原理）；
   - **【案例】判断题**：给一段真实感的豆袋文案 / 冲煮记录 / 店里对话，
     问"问题在哪、下一步怎么调"，答案册必须给**完整推理链**；
   - **【辨识】题**：指向正文给出的权威资料（品种目录、感官词典等），让读者自己去核对。
4. **本章实操**：读者**不一定有器具和豆子**，所以每个实操写成两档：
   - **🅐 无器具版**（读豆袋 / 查官方资料 / 翻自己的购买记录 / 只用嘴和鼻子，随时能做）；
   - **🅑 有条件版**（需要磨豆机、秤、温度计、TDS 计、滤杯等，标注"备齐后再做"，
     **列清所需器具与替代方案**）。
   实操要给**可填写的记录表**（Markdown 表格或链到 [`docs/forms/`](docs/forms/)），
   让观察沉淀下来。
5. **🔎「买豆与冲煮时的用处」**：把本章原理翻译成一两句**可执行的判断**。

风格：像给同事讲清楚一件事，多用"为什么"，诚实标注反直觉/局限（"诚实说明"）。
**绝不写"这么冲一定不好喝"这类绝对断言**——写"出现 X 时，先怀疑 Y，用 Z 来验证"。

## 3. 单一真源 & 可移植 Markdown（核心原则）

- **内容只存一份**：正文 `docs/`。网页/PDF 都是它的渲染。
- **可移植 Markdown**：必须在 **GitHub 原生渲染 + 普通 Markdown 阅读器 + MkDocs** 三边都能看：
  - 用**脚注 + 引用块**做注释，**不要**用 MkDocs 专有的 `!!! note` admonition；
  - 术语表锚点、思考题跳转都用**显式 HTML 锚点** `<a id="xxx"></a>`（三边通用）；
  - 不用 `--8<--` / `{{#include}}` 这类构建期引用（纯阅读器看不到）；
  - 站内链接用相对路径 `xxx.md#anchor`，**锚点必须真实存在**（校验脚本会查）。
- **可复用的表单**（冲煮记录表、杯测记录表、豆袋核对清单等）放 `docs/forms/`，
  各章**链接**过去，不复制粘贴。
- **图片版权**：本书**不搬运**他人实拍照片，也不内嵌外链图片。
  要看实物图时，正文给**权威来源的链接**（不下载）+ **文字判据**（"应该看到什么"）。
  自绘示意图用 Mermaid。

## 4. 目录结构与命名

```
docs/                          # 正文（唯一内容真源）
  index.md                     # 首页 / 大纲 / 进度
  roadmap.md                   # 七部分学习路线图（活的大纲，改动记进"调整记录"）
  glossary.md                  # 术语表（中文 + 英文 + 解释，每词条前有 <a id> 锚点）
  standards.md                 # 出处与资料登记（标准编号 / 教材 / 一手网页 + 核对状态）
  forms/                       # 可复用记录表（冲煮记录、杯测记录…）
    index.md
  chapters/NN-partname/        # 每部分一个目录
    00-intro.md                # 该部分开篇导读（每部分都要有）
    NN-name.md                 # 章节，两位数字前缀（全书连续编号）
    summary.md                 # 该部分小结（速查，可选）
    project-PN-xxx.md          # 该部分的实战项目（见 §6）
  qa/NN-name-qa.md             # 思考题答案册（网页可跳转）
scripts/check_book.py          # 校验：锚点 / 出处登记 / 绝对路径 / admonition / 章节结构
mkdocs.yml                     # 站点配置
```

命名对应：第 N 章 → `chapters/PART/NN-name.md`、`qa/NN-name-qa.md`。

## 5. 各类文件的具体约定

**章节 `.md`**：小节用 `## N.x 标题`。术语首次出现加脚注 `[^x]`，脚注体链接到术语表
`[术语](../../glossary.md#anchor)`。章末思考题下写跳转链接：
`> 📖 **参考答案**（想清楚再看）：[Q1](../../qa/NN-name-qa.md#q1) · [Q2](...#q2) · …`

**答案册 `docs/qa/NN-name-qa.md`**：**只记「问题 + 正确答案」**，不记读者作答。每题前加锚点
`<a id="q1"></a>`…。案例题答案要给推理链（"看到什么 → 推出什么 → 还需要确认什么"）。
必须加进 `mkdocs.yml` 的「思考题参考答案」nav（否则 `--strict` 报错）。

**出处标注格式**：正文引用标准写 `ISO 6668`（**不带年份**，避免版本漂移误导），
在 `docs/standards.md` 里登记完整名称、现行版本与要点，并注明"以最新发布版本为准"。
教材与论文引用统一简称（如 *The Craft and Science of Coffee*、*Espresso Coffee*），
同样在 `standards.md` 登记。行业做法写明"**行业惯例**，可能随市场变化"。
自己拿不准的编号或数字，在 `standards.md` 里标 ⚠️ **待核**，正文同时提示。

**术语表**：新术语加到 `glossary.md` 对应主题下，前置 `<a id="slug"></a>`。
咖啡术语要给 **中文 + 英文原词**——因为豆袋、菜单、协议多是英文，读者必须能对上。
`## ` 节标题不许重复（校验脚本会查，重复会让自动锚点相互覆盖）。

## 6. 实战项目（重要：不要一章一个）

- 项目**只挂在部分末尾或关键节点**，同一部分**最多一个**，全书 **5 个**（P1~P5）。
- 项目文档放**所属部分目录**里（`chapters/NN-part/project-PN-xxx.md`），
  nav 排在该部分末尾，**不单独设分区**。
- 项目同样给「🅐 无器具版 / 🅑 有条件版」两档，并给交付物模板（表格 / 决策清单）。

## 7. 画图（Mermaid 优先）

> **随时画图**：只要图比文字更清楚，就配图——这是硬要求，别偷懒用纯文字凑。

- **反应路径 / 分类树 / 工艺流程 / 萃取机理 / 决策树 → Mermaid**：```mermaid 代码块，
  三边都渲染、可 diff。本书最常用：成分—风味对应图、处理法流程图、烘焙反应链、
  萃取三旋钮图、冲煮问题排查决策树。
- **没有可靠数据来源的量化关系，不要画成"像实测数据"的图**；
  必须画时在标题里写明「示意」，并在图注说明这是定性关系。
- **不要用 matplotlib 画带中文的图**：本机没有中文字体，中文会变方框。
  需要静态图时优先 Mermaid，或写成表格。
- **颜色描述**：涉及烘焙度、汤色的图/表，不要只靠色块传达信息（屏幕色差大且色盲不友好），
  必须同时给**文字描述**。

## 8. 新增一章的标准流程（照做）

1. 先列本章的知识链条，**确认每个数值有出处**（查不到就改写法，别编）；
2. 写 `docs/chapters/PART/NN-name.md`
   （概念 + Mermaid/表 + 常见说法辨析 + 思考题 + 本章实操 🅐/🅑 + 🔎）；
3. 写 `docs/qa/NN-name-qa.md`（问题 + 正确答案，q1/q2/… 锚点；案例题给推理链）；
4. 新术语加进 `glossary.md`，新出处加进 `standards.md`，新表格加进 `forms/`；
5. 更新 `mkdocs.yml`（章节 nav + 答案 nav）、`docs/index.md`（进度）、
   `docs/roadmap.md`（状态）；
6. **校验 + 严格构建**（见 §9）全绿后再提交。

## 9. 构建与校验（提交前必做）

```bash
python scripts/check_book.py     # 锚点 / 出处登记 / 绝对路径 / admonition / 章节结构
mkdocs build --strict            # 坏链接或警告即失败（CI 也跑这条）
```

两条全过才提交。仓库级构建（会顺带下发配色与 PWA 生成物）：

```bash
python ../../scripts/build_site.py --only coffee
```

⚠️ `docs/assets/palette.css`、`docs/assets/favicon.svg`、`overrides/main.html`
**由 books.yml 下发生成，不要手写、不要手改**。

## 10. 提交与发布

- 提交信息中文、说清做了什么 + 为什么；**每完成一块可独立成立的内容就提交**，不要攒到最后。
- push 到 `main` 触发**仓库级** workflow（构建全部书）并发布到 GitHub Pages；
  提交信息加书名前缀，如 `coffee: 第 3 章 水`（见根 CLAUDE.md §6）。
- `mkdocs.yml` 配 `site_url` + `repo_url` + `repo_name`；`README.md` 顶部放**在线阅读**链接——
  网页与仓库互相可达。

## 11. 通用约束（来自用户全局规范）

- **不主动写报告文件**（`*.md` 总结、`report_*.json` 等）；结论直接说，除非明确要求导出。
- 需要时间戳用**北京时间**：`TZ='Asia/Shanghai' date '+%Y-%m-%d %H:%M'`。
- **仓库内所有文件禁止出现绝对路径**（尤其带用户名或机器目录布局的）——公开仓库会泄漏个人信息；
  只用相对路径 / 环境变量。聊天里为方便定位可给绝对路径，但**绝不提交进仓库**。
