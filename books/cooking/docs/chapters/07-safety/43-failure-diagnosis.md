# 第 43 章 失败诊断手册：现象 → 原因 → 下次怎么改

失败不是一句“火候不够”。同一现象常有不同原因：菜里水多，可能是食材出水、锅温掉得太多、调料过早加入，或本来就选了湿润目标。诊断的任务不是替这次成品找一句解释，而是让**下一次只改一个可验证变量**。

## 43.1 先记录现象，再猜原因

把“这菜失败了”拆成可以被别人看见或尝到的话：表面没有颜色、中心偏硬、盘底积水、肉发柴、香气闷、口中有焦苦。没有现象，原因就无从区分。

```mermaid
flowchart LR
    A[描述现象] --> B[列出 2~3 个可能原因]
    B --> C[找能区分它们的证据]
    C --> D[下次只改一个变量]
    D --> E[记录结果]
    E --> F[保留 / 修正规则]
```

| 错误的复盘 | 更可用的复盘 |
|------------|--------------|
| “今天火小了。” | “同样一锅食材一次下太多；下锅后声音很快变闷、盘底积水。下次先分两批，其余不变。” |
| “肉老了。” | “最厚处加热时间不明，切片厚薄也不同。下次统一厚度，只改变停火点，并按安全要求验证。” |
| “盐放错了。” | “出锅前才尝；补盐后又加了酱油。下次在汤汁成形后分两次尝，每次只补一种咸味来源。” |

## 43.2 速查表：先处理最可能的路径

| 现象 | 常见的、可区分的原因 | 下次优先检查 / 只改什么 |
|------|------------------------|----------------------------|
| 肉老、柴 | 超过质地窗口；切得过薄；热输入过猛或停留过久 | 记录厚度和停点；只改切法或停火时机之一；安全熟度另行验证 |
| 肉不熟 / 中心冷 | 食材厚、初温低、热没有到中心 | 测最厚处；不以颜色代替安全判断 |
| 青菜出水、发闷 | 表面水多；一次下锅太多；锅温恢复慢；过早加盐 / 酱料 | 擦干、分批或后调味，每次只选一项测试 |
| 表面不上色 | 表面水分高；锅面热输入不足；食物频繁翻动 | 先管理水分，给一面足够接触时间；不把“开大火”当唯一动作 |
| 粘锅、破皮 | 锅面状态不合适；食材表面湿；过早翻动 | 下次固定食材和油量，只改变预热或翻动时机 |
| 汤汁寡、散 | 加水太多；盐、酸、鲜味加入时机不当；收汁未完成 | 先明确目标浓度；只改液体总量或调味时机 |
| 苦、焦 | 局部过热；香辛料 / 糖过早受热；锅底残渣继续烧 | 先观察锅底与颜色；降低局部热负荷或改变下料顺序 |
| 腥 / 异味 | 原料本身、血污或表面水、处理工具、调味掩盖失败 | 先确认来源与生熟分开；把“去异味”和“加香”分开验证 |
| 米饭结团、积水 | 水分管理不足；下锅量过大；饭粒没先松开 | 固定锅和总量，只比较冷藏饭 / 新鲜饭的处理路径 |

这张表不给“万能补救”。如果食材来源、保存或熟度存在安全疑问，优先回到[第 42 章](42-food-safety.md)，不要为了挽救口感继续试吃。

## 43.3 别把相关当原因

一次做菜里常有多件事同时变化：换了锅、换了食材、调味加倍、又临时开大火。即使结果变好，也不知道究竟哪一项有效。

| 要验证的猜想 | 错误对照 | 最小对照 |
|--------------|----------|----------|
| 分批是否减少出水 | 同时换锅、减少总量、晚放盐 | 食材、锅、总量、调味都相同，只改是否分批 |
| 预热是否减少粘锅 | 同时换油、换食材、换火力 | 食材与油相同，只改预热后的下锅时机 |
| 后放盐是否让青菜更干爽 | 同时延长炒制时间 | 时间与份量尽量一致，只改盐的时机 |

家庭对照不必严密到实验室水平；它只需比“凭印象一次改五件事”更能回答问题。

## 43.4 常见说法辨析

| 说法 | 判断 | 更好的替代 |
|------|------|------------|
| “火大就不会出水” | ❌ 过度简化 | 热输入、份量、表面水和调味时机都会影响结果；先定位哪一项变了。 |
| “粘锅就是锅不好” | ⚠️ 可能，但不充分 | 锅面、预热、食材表面水与翻动时机都可参与；用对照判断。 |
| “苦了多加糖就能救” | ⚠️ 常掩盖而非修正 | 先确认是否为焦糊或香料过热；糖也会改变甜度、颜色与质地。 |
| “做坏一次说明这菜不适合我” | ❌ 不成立 | 单次结果信息很少；写下现象并做一个最小改动。 |

## 43.5 思考题

1. 为什么“菜出水”不能直接推出“火太小”？
2. 你想验证“分批炒更干爽”，哪些变量应尽量保持不变？
3. 为什么安全疑问不应进入“失败补救”的普通流程？

## 43.6 本章实操

### 🅐 零成本版：翻译一次失败

从记忆中选一道失败的菜，把抱怨改写成记录：

| 我原先怎么说 | 可观察现象 | 至少两种可能原因 | 下次只改一个变量 | 我将看什么结果 |
|----------------|------------|------------------|------------------|----------------|
| | | | | |

### 🅑 开火版：最小复做

选择风险低、食材熟悉的一道菜，复做一次。开做前在下面填好“只改什么”；其余条件尽量相同。涉及肉、鱼、蛋时，仍按第 42 章的安全流程处理。

| 上次现象 | 本次唯一改动 | 保持不变的条件 | 结果 | 我的解释是否被支持 |
|----------|--------------|----------------|------|----------------------|
| | | | | |

## 43.7 🔎 下次做菜时的用处

下次成品不对时，先写“哪里不对”，再写“可能为什么”，最后只选一个动作。能被下一次推翻的解释，才是能积累的经验。
