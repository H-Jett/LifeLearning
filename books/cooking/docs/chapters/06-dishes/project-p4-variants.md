# 🛠 项目 P4：变体推演——换食材、换设备，把一道菜重做三遍

> **这是第六部分的验收。**
> 会做一道菜，不等于会应对另一把锅、另一种食材或一次突然缺少的时间。这个项目不追求复刻一个标准答案；它要你保住一道菜的**目标状态**，再为改变的条件写出理由充分的替代方案。

## P4.1 交付物与边界

任选本部分的一道菜（番茄炒蛋、清炒青菜、红烧肉、清蒸鱼、水煮肉片、一锅炖、蛋炒饭），做完后留下：

| 交付物 | 内容 | 用处 |
|--------|------|------|
| **① 原版处理方案** | 目标状态、关键步骤、不能丢的条件 | 知道自己真正要保住什么 |
| **② 三种变体卡** | 每次只改变一个条件，并写出补偿动作 | 遇到限制时不靠猜 |
| **③ 一条迁移规则** | “若……，就优先……” | 下次面对陌生菜能先推演 |

**一次只改变一个主条件。** 例如“换成薄锅”与“食材也多一倍”不能同时拿来判断，否则结果无法解释。现实做菜当然会同时发生很多变化；本项目先把它们拆开，才有资格把它们再组合。

```mermaid
flowchart LR
    A[选一道熟悉菜<br/>写目标状态] --> B[找关键约束<br/>火 / 水 / 时间 / 调味]
    B --> C[只改一个条件]
    C --> D[预测会损失什么]
    D --> E[写补偿动作与停点]
    E --> F[记录结果]
    F --> G[形成下一次的选择规则]
```

## P4.2 先把“原版”写成可替换的结构

不要从“先放几勺”开始，而从结果开始。以蛋炒饭为例，目标不是“用了隔夜饭”，而是“饭粒能分开、锅里不积水、蛋有嫩的部分”。隔夜饭只是达成该目标的一种条件；换成新鲜饭时，才知道该补偿的是水分与结块，而不是机械复制步骤。

| 我选的菜 | 我希望入口时是什么状态 | 最关键的两条线 | 哪一步最不能省 | 我用什么现象决定停下 |
|----------|----------------------------|------------------|------------------|------------------------|
| | | | | |

写完后做一次反问：若删掉“食材品牌、锅的型号、精确分钟数”，这张表还剩下什么？剩下的才是可迁移的核心。

## P4.3 🅐 零成本版：纸上推演三次

不需要下锅。把上表的同一道菜，分别放进下列三个情境；每格都必须写出“**变了什么 → 会带来什么风险 → 用什么动作补偿 → 看什么现象停**”。

| 情境 | 只改变的条件 | 预测的风险 | 补偿动作 | 不能再沿用的旧习惯 | 停点 / 纠偏信号 |
|------|--------------|------------|----------|--------------------|----------------|
| A 换食材 | 例如：叶菜换成含水更多的瓜类；五花肉换成瘦肉 | | | | |
| B 换设备 | 例如：厚锅换薄锅；有蒸屉换成带盖锅 | | | | |
| C 换限制 | 例如：时间减半；一顿要同时做两道菜 | | | | |

写完再逐格检查：

1. 我的补偿是在处理**原因**，还是只是在重复原来的动作？
2. 我写的是可观察的停点（“边缘干缩”“锅底无明显游离水”“中心不再硬”），还是一个未经验证的分钟数？
3. 这次真的只改变了一个主变量吗？

如果答不上来，回到本部分对应章节：第 35 章的顺序、第 36 章的水、第 37 章的时间、第 38 章的窄窗口、第 39 章的两段加热、第 40 章的下锅顺序、第 41 章的水分管理。纸上推演的价值正在于暴露这个空白。

## P4.4 🅑 开火版：做其中一个变体，并复盘

从上面三张卡里选**风险最低的一张**实际做。优先使用你熟悉、可充分加热的食材；接触生肉、鱼、蛋后洗手和清洁接触面，熟食不要再碰到用过的生食工具。若没有把握食材是否熟透或保存是否安全，停止品尝，并先按下一部分的食品安全原则处理。

| 热的路径 | | | |
| 水分管理 | | | |
| 调味时机 | | | |

### 过程中：只记录关键转折

不必全程计时。出现下列任一转折时写一笔即可：

| 我看见 / 听见了什么 | 我做的判断 | 我采取的动作 | 结果 |
|----------------------|--------------|----------------|------|
| | | | |
| | | | |
| | | | |

例如，“锅里突然积水”不是失败标签，而是信息：可先问水来自食材、调料还是锅温恢复不过来；再选择分批、沥干、提高预热、改变下料顺序或接受更湿润的目标。哪一个合适，取决于你在 P4.3 写下的约束。

## P4.5 三次重做后的对照表（交付物②）

纸上三次与实际一次不必全都成功。把预测和结果放在一起，才会发现哪些规则只是“听起来对”。

| 变体 | 我想保住的状态 | 改变的条件 | 我的补偿 | 实际结果 | 下次保留 / 放弃什么 |
|------|----------------|------------|----------|----------|----------------------|
| A 换食材 | | | | | |
| B 换设备 | | | | | |
| C 换限制 | | | | | |

给每行最后补一句：**这一次我仍不能排除的变量是 ______。** 例如食材成熟度、切得不均、锅温起点不同。这不是给失败找借口，而是避免用一次偶然结果写出过强结论。

## P4.6 把答案压缩成一条规则（交付物③）

用下面的句式写一条自己的规则，不许使用“看感觉”“适量”“差不多”：

```text
当我想要 __________（目标状态），但 __________（条件改变）时，
我优先改变 __________（顺序 / 火力 / 切法 / 水分 / 调味时机），
并用 __________（可观察现象）判断是否该停或纠偏；
因为我在这次对照里观察到 __________。
```

这条规则要能被下一次推翻或修正。可检验，才会越来越可靠。

## P4.7 自检清单

| 做到了 | 说明 |
|--------|------|
| 先写目标状态，再写操作 | 你在保住结果，不是在背步骤 |
| 三次推演各只改一个主条件 | 你能知道变化大致来自哪里 |
| 每个补偿动作都对应一个风险 | 你不是为“变化”而变化 |
| 用现象而非固定分钟数定义停点 | 方案可跨食材与设备迁移 |
| 写出至少一个未排除变量 | 你知道家庭对照的边界 |

## P4.8 本项目依据

本项目不新设食谱比例或加热时间；它将第六部分已有的判断变成一次可比较的推演。
