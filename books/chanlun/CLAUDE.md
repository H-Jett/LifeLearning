> 仓库级约定（books.yml、统一构建、提交前缀）见根目录 [`CLAUDE.md`](../../CLAUDE.md)。

> 本文件是这本书的开发约定，Claude Code 会自动加载。人类或 AI 在此目录下开发时**必须遵守**。

## 0. 三条前置红线（写任何一章都适用，违反即不许提交）

### 0.1 合规红线（最硬的一条）

中国的证券投资咨询是**特许经营**。监管对「非法荐股」的认定是三要件：
**无资质 + 提供证券投资分析/预测/建议 + 直接或间接获取利益**，
并且明确**「免责声明不构成抗辩」**——认定看行为实质，不看页面上写了什么。

因此本书**禁止**：

- ❌ 出现**任何具体标的的买卖判断**——不写"某股现在是第三类买点"这类话；
- ❌ 出现**6 位股票代码 / 具体股票名称 / 基金名称**（`check_book.py` 强制拦截数字代码）；
- ❌ 对**未来行情**作任何方向性预测（指数点位、涨跌、时间窗口）；
- ❌ 承诺收益、暗示胜率（"必然赢利""100% 安全"只能作为**被审视的原文主张**出现，
  且必须紧跟本书的评注）；
- ❌ 任何收费、引流、社群、课程、打赏入口，或指向此类入口的链接。

本书**只做方法学教学**：讲定义、讲推导、讲怎么用代码把判据实现出来、
讲怎么用历史数据自己检验。**所有例子必须匿名化**（写成"某标的""样本 A"），
读者要看真图就自己去跑代码。

每一章末尾**必须**带一句风险与合规提示（一句即可，不展开说教），措辞见 §5。

### 0.2 版权红线

原著《教你炒股票》（作者网名"缠中说禅"，通称缠师）著作权**仍在保护期内**
（自然人作品：作者终生 + 死亡后 50 年）。因此：

- ✅ **可以**：转述定义与定理（用自己的话）、标注课次出处、对其主张作评注与检验；
- ❌ **不可以**：整段照抄原文、复制其行文风格与章节编排、做成"108 课解读版"；
- ❌ **不可以**：搬运原著配图、网络流传 PDF 的插图，或任何第三方解读版的图表；
- ⚠️ 引用原文时**只引短句**（一句以内），用引用块并注明课次，且必须是**评注的对象**，
  不能拿来充当本书正文。
- ❌ 原著中的荐股解盘、人身攻击、荤段子、自我评价（"前无古人""如欧几里德之于几何"）
  **一律不进本书**；确需提到其自我定位时，作为"原著的表述"客观陈述并评注。

### 0.3 健康与克制

本书**不鼓励交易**。每章实操分两档，**两档都不要求读者真实下单**
（🅐 手工标注、🅑 跑代码），这是硬规定，不是建议。

## 1. 这是什么

一本"边学边记"的缠论入门书，**双目标**：

1. **讲透**：把缠论的定义链条（分型 → 笔 → 线段 → 中枢 → 走势类型 → 级别 → 背驰 →
   三类买卖点）讲到读者能自己在图上标出来、能自己写成代码；
2. **可检验**：把每一条主张的**性质**说清楚——哪些是定义、哪些是定义的推论、
   哪些是经验断言、哪些不可证伪，并把能跑的都跑一遍。

面向零基础但要求讲透原理的读者。最终会成书，所以：

> **⚠️ 内容必须非常正确。**

### 1.1 主题边界

**以原著文本为主体，以调研为扩展**。主线是缠论本身，不是技术分析通识，
也不是对缠论的批判文集。第六、七部分的实证与制度内容是**扩展**，
篇幅上不喧宾夺主。

已掌握的一手材料是**第 1–48 课**。⚠️ **分型、笔、线段的严格定义不在这 48 课里**
（在第 62 / 65 / 67 课），写第二部分时**必须另找公开出处并在 `sources.md` 登记**，
不许凭记忆补。同理，第 49 课之后的内容一律标注"未掌握原文，据公开转述"。

### 1.2 正确性纪律（本书与姊妹书的根本差异）

茶 / 珠宝 / 咖啡 / 酒四本书"没有 GPU 可跑"，只能靠查资料。
**这本书不一样：行情数据免费可得，判据可以写成代码，主张可以被数据判定。**
所以本书继承的是 InfraLearning 那套「**真机跑数据自证**」，纪律如下：

1. **命题必须打标签**。正文每提出一条实质性主张，前置四种标签之一：

   | 标签 | 含义 | 处理方式 |
   |---|---|---|
   | 〔定义〕 | 缠论自己规定的东西 | 原样转述 + 标课次，不争论对错 |
   | 〔推论〕 | 从定义严格导出的结论 | **必须给出推导**，并尽量用代码在数据上验证算法自洽 |
   | 〔经验断言〕 | 需要事实检验才知真假 | **必须说明如何检验**，能跑就跑，跑不了写明为什么 |
   | 〔不可证伪〕 | 事后永远为真、事前不给约束 | **标出来并说明理由**，不当作依据使用 |

   这四个标签是本书的核心体例，**每一章都要用**（`check_book.py` 会检查）。

2. **凡是能算的，不要用形容词**。"力度更强""明显背驰"这类说法必须落到
   可计算的定义上（面积、柱体和、区间关系），并给出代码或伪代码。

3. **区分"理论说"与"数据说"**。转述原著结论用「原著认为…（第 NN 课）」；
   本书自己的检验结论用「在本书的样本上…」，并写明**样本范围、复权方式、
   参数、成本假设**——否则结论无意义。

4. **禁止事后选样本**。举例只能用**规则先定、样本后取**的方式；
   如果某个例子是挑出来的，必须明写"这是挑选出来的示例，不构成证据"。

5. **一手优先，来源分级**：原著课文（注明课次）> 交易所规则与监管文件原文 >
   同行评议文献（如 Park & Irwin 综述、Lo-Mamaysky-Wang）> 数据源官方文档
   （Baostock / AKShare）> 公开的缠论转述与实现 > 自媒体、培训机构、社群帖子。
   **培训机构与自媒体一律不作依据**，只能当"圈内存在这种说法"的证据
   （正是「常见说法辨析」的素材）。

6. **警惕自己的记忆**：A 股规则改版频繁（涨跌幅档位、ST 规则、盘后定价、
   做市商、退市标准、印花税率），**默认记忆已经过期**，一律以**沪深北交易所规则原文**
   为准现查现标；查不到现行版本就在 `sources.md` 标 ⚠️ **待核**，正文同时提示。

7. **查不到就别写死数字**。宁可写"这一点缺乏公开数据"，
   **绝不用听起来合理的措辞填补空白**。

## 2. 教学法（每章固定结构）

用**中文**写。每章顺序固定（`scripts/check_book.py` 会检查小节名）：

1. **概念正文**：配图（Mermaid）/ 对照表，命题带〔标签〕，定义带课次；
   能讲"为什么"就不要只讲"是什么"；
2. **「常见说法辨析」**表：逐条列出缠圈流传的说法，标注证据强度
   （✅ 有共识 / ⚠️ 有争议 / ❌ 明确错误 / 缺乏证据）+ 一句理由。
   说明它**为什么流传**（通常是在某个特定情形下确实成立，被过度推广了）；
3. **思考题**（数量按内容而定，不固定），紧扣本章，指向答案册（见 §5）。题型混用：
   - 普通问答（考定义与推导）；
   - **【判读】题**：给一段**文字描述的**走势结构（不给真实标的），
     问"这构成什么、不构成什么、还缺什么条件"，答案册给完整推理链；
   - **【标签】题**：给一句缠圈常见表述，问它属于〔定义〕〔推论〕〔经验断言〕〔不可证伪〕
     的哪一类，为什么；
   - **【查证】题**：让读者自己去查交易所规则原文或数据源文档。
4. **本章实操**，两档（读者**不一定会写代码**，而且**不应该为了做题去交易**）：
   - **🅐 手工版**：现在就能做，**不需要开户、不需要下单、不需要写代码**——
     在打印或截图的历史 K 线上做包含处理、标分型、划笔、框中枢、填记录表；
   - **🅑 代码版**：标注**「装好环境再做」**，列清所需环境（Python、数据源、
     复权方式），产出**可复现**的判定结果。
   实操要给**可填写的记录表**（Markdown 表格或链到 [`docs/forms/`](docs/forms/)）。
5. **🔎「看盘时的用处」**：把本章内容压缩成几条可执行的**观察动作**（不是买卖动作）。
   **每章必有**。
6. **⚖️ 合规与风险提示**：每章结尾一句，见 §5。

风格：像给同事讲清楚一件事，多用"为什么"，诚实标注反直觉与局限。
**绝不写"出现 X 就一定 Y"**——写"按定义，出现 X 时本级别只剩 Y、Z 两种可能，
还需要 W 才能分辨"。

## 3. 单一真源 & 可移植 Markdown（核心原则）

- **内容只存一份**：正文 `docs/`。网页 / PDF 都是它的渲染。
- **可移植 Markdown**：必须在 **GitHub 原生渲染 + 普通 Markdown 阅读器 + MkDocs**
  三边都能看：
  - 用**脚注 + 引用块**做注释，**不要**用 MkDocs 专有的 `!!! note` admonition；
  - 术语表锚点、思考题跳转都用**显式 HTML 锚点** `<a id="xxx"></a>`（三边通用）；
  - 不用 `--8<--` / `{{#include}}` 这类构建期引用（纯阅读器看不到）；
  - 站内链接用相对路径 `xxx.md#anchor`，**锚点必须真实存在**（校验脚本会查）。
- **禁止绝对路径**（公开仓库会泄漏个人信息与目录布局）。
- **可复用的表单**（中枢标注表、背驰记录表、检验预登记表）放 `docs/forms/`，
  各章**链接**过去，不复制粘贴。
- **图片版权**：本书**不搬运**任何他人图片，也不内嵌外链图片。
  需要示意图就用 Mermaid 或自写 SVG；需要看真实走势就让读者跑 🅑 档代码自己生成。

## 4. 目录结构与命名

```
docs/                          # 正文（唯一内容真源）
  index.md                     # 首页 / 大纲 / 进度 / 免责声明
  roadmap.md                   # 七部分学习路线图（活的大纲，改动记进"调整记录"）
  glossary.md                  # 术语表（中文 + 原著用词 + 英文，每词条前有 <a id> 锚点）
  sources.md                   # 出处与资料登记（课次 / 规则 / 文献 / 数据源 + 核对状态）
  notation.md                  # 记号速查（ZG/ZD/GG/DD、a+A+b+B+c、Zn 等）
  forms/                       # 可复用记录表
    index.md
  chapters/NN-partname/        # 每部分一个目录
    00-intro.md                # 该部分开篇导读（每部分都要有）
    NN-name.md                 # 章节，两位数字前缀（全书连续编号）
    summary.md                 # 该部分小结（速查，可选）
    project-PN-xxx.md          # 该部分的实战项目（见 §6）
  qa/NN-name-qa.md             # 思考题答案册（网页可跳转）
scripts/check_book.py          # 校验：合规 / 锚点 / 课次登记 / 绝对路径 / 章节结构
mkdocs.yml                     # 站点配置
overrides/                     # PWA 注入，由仓库级 build_site.py 生成，勿手写
docs/assets/                   # palette.css / favicon.svg，由 books.yml 下发，勿手改
```

命名对应：第 N 章 → `chapters/PART/NN-name.md`、`qa/NN-name-qa.md`。

七个部分的目录名固定为：
`01-foundation`（入门与地基）、`02-geometry`（可计算的几何层）、
`03-pivot`（中枢）、`04-divergence`（力度与背驰）、
`05-signals`（三类买卖点）、`06-practice`（多义性与实战判读）、
`07-reality`（落到 A 股现实）。

## 5. 各类文件的具体约定

**章节 `.md`**：小节用 `## N.x 标题`。术语首次出现加脚注 `[^x]`，脚注体链接到术语表
`[术语](../../glossary.md#anchor)`。章末思考题下写跳转链接：
`> 📖 **参考答案**（想清楚再看）：[Q1](../../qa/NN-name-qa.md#q1) · [Q2](...#q2) · …`

**课次引用格式**：写成 `第 17 课`（阿拉伯数字 + 空格），并在 `sources.md` 的课次表里
登记该课的标题与本书用到了它的什么。`check_book.py` 会强制未登记的课次报错。
⚠️ 第 49 课及之后本书**未掌握原文**，引用时必须写成
「据公开转述，第 NN 课…（未见原文，见 sources.md）」。

**合规提示的标准措辞**（每章结尾，照抄即可，不要改写成更软的版本）：

```
> ⚖️ 本书只讲方法与检验，不推荐任何标的、不预测行情、不构成投资建议。
> 市场有风险，任何据此产生的后果由读者自负。
```

**术语表**：新术语加到 `glossary.md` 对应主题下，前置 `<a id="slug"></a>`。
缠论术语要给 **本书用词 + 原著用词 + 英文**——因为原著用词（如"缠中说禅走势中枢"）
与圈内简称（"中枢"）并存，读者必须能对上。`## ` 节标题不许重复（校验脚本会查）。

**记号**：全书统一用 `notation.md` 里的记号，不要各章自创。
中枢区间一律写 `[ZD, ZG]`，趋势结构一律写 `a+A+b+B+c`。

## 6. 实战项目（重要：不要一章一个）

- 项目**只挂在部分末尾**，同一部分**最多一个**，全书 **5 个**（P1~P5）。
- 项目文档放**所属部分目录**里（`chapters/NN-part/project-PN-xxx.md`），
  nav 排在该部分末尾，**不单独设分区**。
- 项目同样给「🅐 手工版 / 🅑 代码版」两档，并给交付物模板（表格 / 判定清单）。
- 🅐 档同样**不要求开户与下单**。

## 7. 画图（Mermaid 优先）

> **随时画图**：只要图比文字更清楚，就配图——这是硬要求，别偷懒用纯文字凑。

- **定义链条 / 判定流程 / 中枢结构 / 递归关系 / 决策树 → Mermaid**：用 mermaid 围栏代码块，
  三边都渲染、可 diff。本书最常用：定义依赖图、包含处理流程、中枢生住坏灭状态图、
  走势类型分解树、背驰判定流程、三类买卖点与中枢的位置关系图。
- **K 线示意图 → 自写 SVG**：需要画具体 K 线形态（分型、笔、中枢区间）时写内联 SVG，
  文字由浏览器渲染，可 diff、无版权问题。
  ⚠️ **不要用 matplotlib 画带中文的图**：本机没有中文字体，会变方框。
- **数据图表**：**只在有可复现代码与明确样本说明时才画**，图注必须写
  样本范围 / 复权方式 / 参数 / 成本假设；没有就不要画成"像实测数据"的样子。
- **颜色**：⚠️ **不要用红涨绿跌的配色承载信息**——A 股与欧美市场红绿含义相反，
  且色盲不友好。用形状、标注文字、线型区分，颜色只作辅助。

## 8. 新增一章的标准流程（照做）

1. 先列本章的**定义链条**，标出每条命题属于〔定义〕〔推论〕〔经验断言〕〔不可证伪〕哪一类；
2. 为每个课次引用、每条规则、每个数字找到出处（查不到就改写法，别编）；
3. 写 `docs/chapters/PART/NN-name.md`（概念 + Mermaid/SVG + 常见说法辨析 +
   思考题 + 本章实操 🅐/🅑 + 🔎 用处 + ⚖️ 合规提示）；
4. 写 `docs/qa/NN-name-qa.md`（问题 + 正确答案，`q1`/`q2`/… 锚点；判读题给推理链）；
5. 新术语加进 `glossary.md`，新出处加进 `sources.md`，新记号加进 `notation.md`；
6. 更新 `mkdocs.yml`（章节 nav + 答案 nav）、`docs/index.md`（进度）、
   `docs/roadmap.md`（状态）；
7. **校验 + 严格构建**（见 §9）全绿后再提交。

## 10. 提交与发布

- 提交信息中文、说清做了什么 + 为什么；**每完成一块可独立成立的内容就提交**，不要攒到最后。
- 提交信息加书名前缀，如 `chanlun: 第 12 章 中枢的定义`（见根 CLAUDE.md §6）。
- push 到 `main` 触发**仓库级** workflow（构建全部书）并发布到 GitHub Pages。

## 11. 通用约束（来自用户全局规范）

- **不主动写报告文件**（`*.md` 总结、`report_*.json` 等）；结论直接说，除非明确要求导出。
- 需要时间戳用**北京时间**：`TZ='Asia/Shanghai' date '+%Y-%m-%d %H:%M'`。
- **仓库内所有文件禁止出现绝对路径**（尤其带用户名或机器目录布局的）——公开仓库会泄漏个人信息；
  只用相对路径 / 环境变量。聊天里为方便定位可给绝对路径，但**绝不提交进仓库**。
