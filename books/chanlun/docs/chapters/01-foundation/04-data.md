# 第 4 章 · 拿到可复现的行情

> 前三章都在讲"应该怎么判"。这一章讲"拿什么去判"。
> 本章不照抄任何数据源对比文章——所有结论都是**当场实测**的，
> 测试日期、环境、样本范围全部写明。你照着做一遍，很可能得到**不同的结果**，
> 而这恰恰是本章最重要的一课。

## 4.1 "可复现"到底要求什么

〔定义〕一份行情数据是**可复现的**，如果：
**同样的取数参数，在不同时间、不同机器上执行，得到逐行相同的序列。**

听起来是句废话，但它至少排除掉三种常见做法：

| 做法 | 为什么不可复现 |
|---|---|
| 从行情软件导出 CSV | 复权方式、时段口径、数据版本都没有记录 |
| 用默认参数调接口 | "默认"会随库版本变化；半年后重跑可能换了复权方式 |
| 用前复权序列 | 历史价格会被后续除权重写（第 2 章 2.3 节） |

所以本书的取数纪律只有四条，但一条都不能省：

1. **复权方式显式指定**，不用默认；
2. **要复现的分析用后复权**，或存下带日期戳的前复权快照；
3. **取数日期、数据源、版本号记录下来**；
4. **原始数据落盘**，不要每次重新拉——上游随时可能改。

## 4.2 实测：本书环境下能拿到什么

> ⚠️ **下表是一次具体的测量，不是普遍事实。**
> 测试日期 **2026-09-12**，环境为一台境内服务器。
> 结果**强烈依赖你的网络出口**——见 4.3 节。
> 完整登记见[出处与资料](../../sources.md)第五节。

### Baostock

| 测试项 | 实测结果 |
|---|---|
| 登录 | 成功，免注册、免 token |
| 日线覆盖 | 每个样本 2835 个交易日（2015-01-01 ~ 2026-09-01） |
| 复权方式 | 三档可选：不复权 / 后复权 / 前复权，**由参数显式指定** |
| 30 分钟线 | 可取，支持后复权；**每个交易日恰好 8 根** |
| 5 分钟线 | 可取，支持后复权；本次取到 77568 行，**最早起始 2020-01-02** |
| 逐笔成交 | 未提供 |

**"每日恰好 8 根 30 分钟 K 线"** 这条实测，正好印证了第 3 章 3.3 节算出来的
"A 股每日连续竞价 4 小时 → 30 分钟 → 日是 8 倍"。
第 3 章是从规则算出来的，这里是从数据数出来的，两者对上了。

**5 分钟线最早只到 2020 年初**——这条很重要：
它意味着**小级别的历史检验，样本长度受限于数据源而不是受限于方法**。
第六部分做检验时必须把这个约束写进预登记表。

### AKShare

| 测试项 | 实测结果 |
|---|---|
| 安装与导入 | 成功 |
| 日线（后复权 / 不复权） | ❌ 连接被远端中断 |
| 30 分钟线、1 分钟线 | ❌ 连接被远端中断 |

四个接口全部失败，报的都是同一类错误：**远端在没有返回任何内容的情况下关闭了连接**。

这**不能**被解读成"AKShare 不可用"。正确的解读是下一节的主题。

## 4.3 本章最重要的一课：数据可得性不是数据源的属性

〔推论〕**"某个数据源能不能用"不是一个关于该数据源的事实，
而是一个关于"你的网络出口 × 上游站点当前策略 × 库版本"的三元组的事实。**

这是从 4.2 节那个失败里直接得到的结论。原因：

- **Baostock 有自己的服务端**，客户端直连它；
- **AKShare 本质是一组第三方站点的爬虫**——它去抓行情站、财经站的接口。
  上游站点改版、限流、或按来源封禁，接口就失效，
  而这一切**与 AKShare 的代码质量无关**。

所以在本书的测试环境下，AKShare 全挂而 Baostock 全通；
换一台机器、换一个出口，结论完全可能反过来。

> **这条推论的实际用法**：
> 看到任何"数据源对比"文章（包括本章），**先问它是在什么环境测的、什么时候测的**。
> 没写这两样的对比表，参考价值接近零。
> 同理，本书 4.2 节的表**必须**带着"2026-09-12、境内服务器"这两个限定读。

〔经验断言〕"免费数据源能否稳定支撑缠论的小级别分析" ——
这条断言**没有一个与时间无关的答案**。它需要你在自己的环境里、
在开始做检验之前，实测一次并记录下来。这就是本章 🅑 档实操。

## 4.4 实测：未复权到底害在哪

第 2 章说过未复权序列会制造假缺口。这个说法对，但**不够精确**——
精确到什么程度，可以量出来。

**测量方法**：对同一个样本，分别取不复权与后复权的日线收盘价，
算出两条日收益率序列。两者出现实质差异的日子，就是**除权事件日**
（正常交易日两条序列的收益率应当一致）。

**实测结果**（7 个样本，各 2835 个交易日，合计 19845 个交易日，
区间 2015-01-01 ~ 2026-09-01，数据源 Baostock，测试日期 2026-09-12）：

| 指标 | 实测值 |
|---|---|
| 每个样本的除权事件数 | 3 ~ 23 次 |
| 除权事件占交易日比例 | 约 0.5% |
| **单次除权造成的最大价格跳变** | **67.3%** |
| 各样本最大除权跳幅 | 5.7% / 5.9% / 10.8% / 45.9% / 47.3% / 50.3% / 67.3% |
| 按"日收益绝对值 > 3%"计数：不复权 | 2386 次 |
| 同上：后复权 | 2352 次 |
| **未复权序列"虚增"的大跳变次数** | **34 次（约 0.17%）** |

现在看这组数字，会得到一个**和直觉相反、但很有用**的结论：

〔推论〕**未复权的危害不在"多"，在"极端"。**

- 从**频次**看，未复权只多出 34 次大跳变，占全部交易日的 0.17%——
  少到几乎可以忽略；
- 但从**幅度**看，这些跳变里包含了 45.9%、47.3%、50.3%、67.3% 这种量级的跳空，
  **远远超出任何正常交易日的波动**。

而缠论的判据是**结构性**的，不是统计性的：

> 中枢是不是成立，取决于三段区间**有没有共同重叠**。
> 一次 67% 的假跳空，**一次就足以**把本该重叠的三段撕开，
> 让中枢凭空消失或凭空出现。接着走势类型、级别、背驰全部级联出错。

〔推论〕**用"假缺口出现的频率"来评估未复权的危害，会严重低估它。**
正确的评估方式是看**最大幅度**——因为这里的损害是非线性的：
0.17% 的坏数据可以毁掉一个完整的分解链。

> 顺便说一句：这也是为什么第 2 章的 🅑 档实操要同时统计**次数和最大幅度**。
> 只看次数会得出"未复权问题不大"这个错误结论。

## 4.5 取数清单

把前面几节压成一份可照做的清单。

**取数前决定并记录**：

| 项 | 本书默认 | 为什么 |
|---|---|---|
| 复权方式 | 后复权 | 历史不被重写（第 2 章 2.3 节） |
| 数据源 | 有自有服务端的优先 | 爬虫型数据源的可得性依赖出口（4.3 节） |
| 区间 | 显式起止日期 | "最近 N 年"不可复现 |
| 频率 | 显式 | 并记录该频率的**历史深度上限** |
| 取数日期 | 记录 | 上游会改版 |
| 库版本 | 记录 | 默认参数会随版本变 |

**取数后做体检**（复用第 2 章 🅑 档写的脚本）：

| 体检项 | 期望 | 不符合时 |
|---|---|---|
| 行数 vs 交易日历 | 一致 | 差额即疑似停牌，单独列出 |
| 成交量为 0 的行 | 0 行 | 说明混入了停牌占位行，应剔除并记录 |
| 相邻日跳变的**最大值** | 无极端值 | 有 → 查是否除权未处理 |
| 一字线占比 | 记录下来 | 高 → 该样本的级别判定不可靠（第 2 章 2.4 节） |
| 日期是否严格递增、有无重复 | 是 | 否 → 数据源问题，换源或去重并记录 |
| 每日 K 线根数（分钟频率） | 恒定 | 不恒定 → 时段口径有问题 |

**落盘**：原始数据存成带日期戳的文件，**之后所有分析读这份快照**，
不要每次重新拉。上游一改，你之前所有结论就失去可复现性。

## 常见说法辨析

| 说法 | 证据强度 | 辨析 |
|---|---|---|
| "某某数据源最好用" | ⚠️ 缺乏证据 | 除非说明了测试环境与日期，否则这句话没有信息量。本章实测里 AKShare 四个接口全失败、Baostock 全通——换个网络出口结论完全可能反过来（4.3 节） |
| "未复权问题不大，除权又不常见" | ❌ 明确错误 | 频次确实低（实测约 0.5% 的交易日），但**单次跳幅实测最高 67.3%**。缠论的中枢判定是结构性的，一次极端假跳空就能撕裂整条分解链。用频次评估危害会严重低估 |
| "免费数据够做缠论了" | ⚠️ 有争议 | 日线够。但实测显示 5 分钟线的历史深度受限（本次最早只到 2020 年初），逐笔完全拿不到——而逐笔恰恰是原著定义的最低级别（第 35 课）。所以小级别的**历史检验**能做到什么程度，取决于数据而不是方法 |
| "前复权和后复权差不多，都能消掉跳空" | ⚠️ 有争议 | 消跳空的效果确实一样（本章实测两者的大跳变计数完全相同）。差别不在这里，在于**前复权的历史会被后续除权重写**，因而不可复现。用途不同，不是谁更准 |
| "接口报错就是数据源挂了" | ❌ 明确错误 | 爬虫型数据源报错，更常见的原因是上游站点改版或按来源限流。判断之前先换个网络环境试一次 |
| "拉一次数据就行，每次现拉更新鲜" | ❌ 明确错误 | 每次现拉 = 每次可能拿到不同的历史（上游改版、复权重算）。要可复现就必须**落盘快照**，分析读快照 |

## 思考题

**Q1.** 本书规定"要复现的分析必须用后复权"。
本章实测显示前复权和后复权在"消除大跳变"上效果完全相同。
那么这条规定的理由是什么？请不要答"因为第 2 章说了"，要说出机制。

**Q2.**【判读】某人说："我测了，AKShare 拿不到数据，所以这个库不能用。"
指出这句话的问题，并说出要得到一个有意义的结论，他还需要补充什么。

**Q3.**【标签】"未复权的危害不在多，在极端"属于〔定义〕〔推论〕〔经验断言〕
〔不可证伪〕中的哪一类？本章是怎么支持它的？

**Q4.** 本章实测发现未复权序列只"虚增"了约 0.17% 的大跳变。
有人据此说"那用未复权也无所谓，误差 0.2% 而已"。
请用中枢的定义解释这个推理错在哪。

**Q5.**【判读】某人要检验"某个 5 分钟级别的判据在过去十年的表现"。
结合本章 4.2 节的实测结果，指出他会遇到什么问题，以及应该怎么调整他的研究设计。

**Q6.**【查证】在你自己的环境里，把 4.2 节的测试跑一遍。

这说明本章那张表应该被当成什么——事实，还是别的什么？

## 本章实操

两档都**不需要开户、不需要下单**。

### 🅐 手工版：核对一次复权价

**需要**：任意行情软件 + 该标的的分红送转公告（交易所网站或软件的除权信息里能查到）。

1. 找一个**大比例送转**的除权事件（比例越大越好，本章实测里最大的一次跳幅超过 60%）。
2. 记下除权日**前一交易日的收盘价**（不复权）与**除权日的开盘参考价**。
3. 按公告的送转与分红比例，**自己手算**一次除权参考价。
4. 和软件显示的对比，看对不对得上。
5. 把这个"跳空"的幅度写下来，然后问自己一个问题：
   **如果这个跳空出现在你要划中枢的三段之间，会发生什么？**

第 5 步是重点。手算一遍除权价，比读十遍"要复权"这句话都管用。

### 🅑 代码版：写你自己的环境实测报告

**需要**：Python 环境 + 第 2 章 🅑 档的体检脚本。
**先填[检验预登记表](../../forms/prereg-template.md)再动手。**

**第一步：能力实测**

对你打算用的每一个数据源，逐项测并记录：

| 测什么 | 记什么 |
|---|---|
| 能否连通 | 成功 / 失败 + 具体错误类型 |
| 日线支持的复权方式 | 有哪几档、参数名是什么 |
| 各频率的**历史深度** | 最早能取到哪一天（这是硬约束） |
| 分钟线的复权支持 | 支持 / 不支持 |
| 每日 K 线根数是否恒定 | 恒定值是多少（对照第 3 章的周期阶梯） |
| 逐笔数据 | 有 / 无 |

**必须同时记录**：测试日期、网络环境、库版本。
没有这三样，你的报告和网上那些没头没尾的对比文章没有区别。

**第二步：复权危害量化**

复现本章 4.4 节的测量，但**换你自己的样本**：

1. 同一批样本各取一次不复权与后复权日线；
2. 算两条日收益率序列，**差异超过阈值的日子 = 除权事件日**；
3. 报告三个数，**缺一不可**：
   - 除权事件的**次数**；
   - 单次除权造成的**最大跳幅**；
   - 按某阈值计数时未复权序列"虚增"的次数。
4. 对照本章的实测值，看你的样本是更极端还是更温和。

⚠️ **只报告次数不报告最大幅度的，本章白学了**——4.4 节的整个论点就是
频次会低估危害。

**第三步：落盘**

把原始数据存成带日期戳的快照，之后所有章节的 🅑 档都读这份快照。
把实测结果登记进[出处与资料](../../sources.md)第五节。

## 🔎 看盘时的用处

1. **看到任何数据源对比，先找测试日期和环境。** 没有这两样就当没看见。
2. **自己的结论也要带这两样。** 否则半年后你自己都不知道当时测的是什么。
3. **换机器、换网络之后重测一次。** 可得性不是数据源的属性。
4. **评估数据问题时看最大值，不只看频率。** 结构性判据怕的是极端值，不是平均值。
5. **原始数据落盘。** 这是可复现的最低成本做法，也是最容易被省掉的一步。
