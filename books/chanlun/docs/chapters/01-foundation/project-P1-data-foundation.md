# 🛠 项目 P1 · 搭一个可复现的行情底座

> 第一部分的收尾项目。做完它，你手上会有**一份冻结的、体检过的、口径写明白的行情数据**，
> 以及**一份你自己环境的实测报告**。
> 后面每一章的 🅑 档实操都读这份底座——所以这个项目的质量决定了后面所有结论的质量。

## 为什么这是第一个项目

第 1 章说缠论的目标是"两个人能对账"。但对账有个前置条件：
**两个人得看的是同一份数据**。而第 2、4 章已经说明，
"同一份数据"在 A 股比想象中难得多——复权方式、历史深度、停牌、
数据源可得性，每一项都能让两份看起来一样的数据其实不一样。

所以在学几何层之前先做这件事，理由很直接：

> **一个建立在错数据上的正确算法，输出的是错误答案；
> 而你不会知道，因为算法本身没报错。**

## 交付物

做完这个项目，你应该有下面四样东西。**四样缺一不可**——
少任何一样，这份底座就不满足第 4 章 4.1 节对"可复现"的定义。

| # | 交付物 | 形式 | 作用 |
|---|---|---|---|
| 1 | **口径声明** | 一份表格 / 一个配置文件 | 写死取数的全部参数，别人照着能取到一样的数据 |
| 2 | **数据快照** | 落盘的文件，文件名带日期 | 冻结。之后所有分析读它，不重新拉 |
| 3 | **体检报告** | 一份表格 | 这份数据有哪些已知问题，分别有多严重 |
| 4 | **环境实测报告** | 一份表格 | 你的环境能拿到什么、拿不到什么、测于何时 |

## 🅐 手工版：不写代码也能做

**需要**：任意行情软件 + 一个表格工具（纸笔也行）。

不写代码不代表做不了这个项目——**口径声明与体检的思路和代码版完全一样**，
只是样本量小。手工做一遍的好处是：你会对每一项检查**为什么存在**有实感。

### 第一步：写口径声明

先填这张表，**填完再去取数**。顺序很重要——先定口径再取数，
才不会变成"取到什么算什么"。

| 项 | 你的选择 | 备注 |
|---|---|---|
| 样本 | | 匿名化编号，如"样本 A / B / C"；建议 3~5 个，跨行业 |
| 频率 | | 建议先从日线开始 |
| 区间（起止日期） | | 写死，不写"最近几年" |
| **复权方式** | | 后复权（要复现）或带日期戳的前复权快照 |
| 数据来源 | | 软件名 + 版本 |
| 导出日期 | | |

### 第二步：导出并冻结

从软件导出这几个样本的数据，存成文件，**文件名里带上导出日期**。
之后所有操作都在这份文件上做——**不要回软件里重新看**，
因为软件显示的可能已经变了（前复权尤其）。

### 第三步：人工体检

对每个样本，逐项检查并填表：

| 体检项 | 怎么手工查 | 你的结果 |
|---|---|---|
| 行数 | 数一下，和交易日历对照 | |
| 日期是否有重复或倒序 | 排序看一眼 | |
| **相邻日跳变最大的那天** | 算一列 `今收 / 昨收 − 1`，找绝对值最大的 | |
| 那天是不是除权日 | 去查该标的的分红送转公告 | |
| 一字线（开=高=低=收）有几天 | 筛一下 | |
| 日期有没有跳过（疑似停牌） | 看相邻日期间隔 | |

⚠️ **第三行是重点**。第 4 章 4.4 节的实测结论是"未复权的危害不在多、在极端"——
所以体检要找的是**最大值**，不是平均值。

### 第四步：做一次对照

这一步是手工版的精华，**别跳过**：

把**同一个样本**再导出一份**未复权**的数据，
和第二步那份复权数据放在一起，回答：

1. 两份数据里，"相邻日跳变最大"的那一天**是同一天吗**？
2. 未复权那份的最大跳幅是多少？复权那份呢？**差多少倍**？
3. 如果你要在跳变最大的那一天前后划一个中枢，两份数据会给出**一样的结论吗**？

第 3 问答不上来也没关系——把问题记下来，等学完第三部分回来看。

## 🅑 代码版：写一个可复用的底座

**需要**：Python 环境 + 至少一个能连通的数据源。
**先填[检验预登记表](../../forms/prereg-template.md)再动手。**

### 模块一：口径声明

把取数参数写成一个**显式的配置**，不要散落在代码里：

```text
必须显式指定、不许用默认值的项：
  symbols       样本列表
  freq          频率
  start / end    区间（写死日期，不用相对时间）
  adjust        复权方式          ← 最容易被默认值坑的一项
  source        数据源 + 版本号
  fetched_at    取数日期
```

〔推论〕**凡是用了默认值的参数，都不满足可复现**——
默认值会随库版本变化，半年后重跑可能换了复权方式而你不知道。

### 模块二：取数与落盘

```text
1. 按配置取数
2. 立刻落盘为带日期戳的文件
3. 把配置本身也一起存进去（或存成同名的配置文件）
4. 之后所有分析读快照，不再调接口
```

⚠️ 第 3 步经常被省略，但它才是关键：**数据和它的口径必须存在一起**。
一份不知道复权方式的 CSV 和没有这份数据差不多。

### 模块三：体检

把第 2 章 🅑 档写的体检脚本整理成一个函数，输出一张表：

| 体检项 | 期望 | 不符合时怎么办 |
|---|---|---|
| 行数 vs 交易日历 | 一致 | 差额列为疑似停牌，单独记录**不要**静默补齐 |
| 日期严格递增、无重复 | 是 | 否则是数据源问题，去重并记录 |
| 成交量为 0 的行 | 0 行 | 有 → 混入了停牌占位行，剔除并记录数量 |
| 相邻日跳变的**最大值** | 记录下来 | 极端值 → 查是否除权未处理 |
| 疑似除权日 | 记录日期列表 | 与公开的除权信息对照 |
| 一字线占比 | 记录下来 | 高 → 该样本级别判定不可靠（第 2 章 2.4 节） |
| 分钟频率：每日 K 线根数 | 恒定 | 不恒定 → 时段口径有问题 |
| 缺失值 | 0 | 有 → **不要填充**，记录位置 |

〔推论〕**体检报告的价值不在"全部通过"，而在"已知问题清单"。**
一份写着"有 3 次停牌、2 次除权、一字线占 1.2%"的报告，
远比一份写着"全部通过"的报告有用——
因为后面某章的结论出问题时，你有地方去查原因。

### 模块四：环境实测报告

复现第 4 章 4.2 节的测试，但**用你自己的环境**：

| 记什么 | 为什么 |
|---|---|
| 测试日期 | 上游策略随时变 |
| 网络环境 | 可得性取决于出口（第 4 章 4.3 节） |
| 各库版本号 | 默认参数会随版本变 |
| 每个接口：成功 / 失败 | 失败要记**具体错误类型**，不只是"失败" |
| 各频率的**历史深度** | 这是硬约束，会限制后面所有检验的样本长度 |
| 是否支持逐笔 | 对应原著定义的最低级别（第 35 课） |

**失败的也要记。** 只记成功的那个源，半年后接口失效时，
你会完全不记得当初试过什么、为什么没选另一个。

## 验收标准

这个项目做到什么程度算完成？下面每一条都要能回答"是"：

- [ ] 把口径声明交给另一个人，他能取到**逐行相同**的数据吗？
- [ ] 数据快照的文件名里有日期吗？配置和数据存在一起吗？
- [ ] 体检报告里的"已知问题清单"是**具体的**吗（有日期、有数量、有幅度），
      还是只写了"正常"？
- [ ] 环境实测报告里，**失败的接口**也记了具体错误吗？
- [ ] 你知道自己这份数据的**历史深度上限**吗？
- [ ] 如果三个月后重跑，你有办法验证拿到的还是同一份数据吗？

最后一条最容易被忽略。一个简单做法：**给快照算一个校验和并记下来**。

## 常见的坑

| 坑 | 症状 | 怎么避 |
|---|---|---|
| 用默认复权方式 | 半年后重跑结果对不上 | 永远显式指定 |
| 用前复权做分析 | 历史被后续除权重写 | 用后复权，或冻结前复权快照 |
| 请求区间超出数据源历史深度 | **接口不报错**，静默返回它有的那部分 | 取完先核对行数与起止日期 |
| 用自然日期做位置计算 | 停牌导致错位 | 用**交易日序号** |
| 静默填充缺失值 | 凭空造出不存在的 K 线 → 假分型 | 不填充，记录位置 |
| 每次分析都重新拉数据 | 上游一改，历史结论无法复现 | 读快照 |
| 只记录成功的数据源 | 接口失效时不知道备选 | 失败也记 |
