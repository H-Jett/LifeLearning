# 🛠 项目 P4 · 把三类买卖点写成判定函数

> 第五部分的收尾项目。目标是产出一个**可复现的结构识别器**——
> 输入行情与约定集，输出带类型标注的买卖点序列。
>
> ⚠️ 这是一个**结构识别器**，不是交易系统。它不产生任何操作建议，
> 也不评估任何收益——那是第六部分的事，而且要按完整流程来。

## 为什么现在做这个

第六部分要检验"这些买卖点有没有用"。而检验的前提是：

〔推论〕**被检验的对象必须是一个确定的函数。**

如果买卖点的判定里还有任何"看情况""凭感觉"的成分，
那么检验的就不是缠论，而是判定者本人——结果既不可复现，也无法归因。

所以 P4 的产出是第六部分的**输入**。

## 交付物

| # | 交付物 | 作用 |
|---|---|---|
| 1 | 22 项约定的配置 | 让判定可复现 |
| 2 | 三类买卖点的判定函数 | 被检验的对象 |
| 3 | 全套自检断言 | 保证实现与定义一致 |
| 4 | 信号序列（冻结导出） | 第六部分的输入 |
| 5 | 约定敏感性报告 | 知道结论有多稳 |

## 🅐 手工版：写一份判定清单

不写代码也能做这个项目——**把判定过程写成一份任何人都能照着走的清单**，
本质上就是一个"人肉函数"。

### 第一步：抄下约定

把 22 项约定填进一张表（第 11 章 16 项 + 第 13/14/15/19/21/24 章 6 项）。

### 第二步：写三张判定卡

每一类买卖点写一张卡，格式固定：

```text
【第 N 类买点判定卡】
前置条件：
  □ ⋯（逐条列出）
判定步骤：
  1. ⋯
  2. ⋯
输出：
  □ 通过 → 记录位置、级别、依据
  □ 不通过 → 记录挡在第几步
```

⚠️ **每一步都必须是"任何人照着做都能得到同样结果"的**。
凡是写出"判断一下""看起来"的地方，都说明这一步还没想清楚——
回去把它拆成可执行的判据。

### 第三步：交叉验证

把三张卡交给另一个人，让他对同一段数据走一遍。

- 结果一致 → 你的卡是一个合格的"函数"；
- 不一致 → 找出分歧点，**把那一步写得更死**，重做。

这一步是手工版的核心。**卡片的质量由"别人能不能复现"来衡量，
而不是由"我自己用着顺手"来衡量。**

### 第四步：统计

用你的卡对一段历史数据走一遍，统计三类买卖点的数量，
与本书的基线对照：

| 类型 | 本书实测 |
|---|---|
| 第一类（MACD 口径 / 幅度口径） | 8 / 31 |
| 第三类 | 297 |
| 第三类 : 第一类 | 约 37 : 1 |

## 🅑 代码版

**需要**：第 25~30 章的全部实现。

### 第一步：统一接口

把三类判定收拢成一个函数，**约定集作为显式参数**：

```text
detect_signals(bars, config) -> [Signal]

Signal 至少包含：
  type        1B / 1S / 2B / 2S / 3B / 3S
  level       在哪个级别上判出的
  index       位置（原始 K 线索引）
  confirmed   已确认 / 待定        ← 不能省（第 11 章 11.3 节）
  basis       依据（对应的中枢、背驰结构等）
  config_hash 约定集的哈希
```

⚠️ `confirmed` 和 `config_hash` 这两个字段是**硬要求**：

- 没有 `confirmed`，实时使用时会用确定的语气说不确定的事（第 30 章 30.2 节）；
- 没有 `config_hash`，日后无法确认某批信号是用哪套约定生成的。

### 第二步：全套自检断言

汇总前面各部分：

| 类别 | 断言 | 出处 |
|---|---|---|
| 几何层 | 14 条 | 第 11 章 11.4 节 |
| 中枢层 | 9 条 | 第三部分（P2） |
| 背驰层 | 5 条 | 第四部分（P3） |
| **买卖点层** | 每个信号能归入三类之一 | 第 28 章 |
| | 一类 & 二类不重合 | 第 26 章 |
| | 一类 & 三类不重合 | 第 26 章 |
| | 三买的回试低点 ≥ 对应中枢 `ZG` | 第 27 章 |
| | 三买之后必是扩张或新生 | 第 27 章 |
| | 状态序列严格交替 | 第 30 章 |
| 全局 | 增量结果 == 全量结果 | 第 11 章 11.3 节 |

**全部通过再往下。**

### 第三步：复现第五部分的实测

| 指标 | 本书实测 |
|---|---|
| 第一类（MACD / 幅度） | 8 / 31 |
| 第三类（买 / 卖 / 合计） | 160 / 137 / 297 |
| 第三类 : 第一类 | 约 37 : 1 |
| 三买后下一笔超越前一同向笔极值 | 66%（n=160） |
| 对照组（任意向上笔） | 49%（n=1020） |

⚠️ 最后两行**只作对照，不作结论**——六个缺口见第 27 章 27.5 节。

### 第四步：约定敏感性

先填[检验预登记表](../../forms/prereg-template.md)。
至少测三项，每项都报告**数量 + 位置重合率**：

| 测什么 | 预期影响 |
|---|---|
| 第 18 项（判不重叠的区间） | **最大**——趋势占比 16.4% ↔ 95.7% |
| 第 20 项（力度度量） | 第一类数量 8 ↔ 31 |
| 第 10 项（成笔失败处理） | 笔端点重合率可低至 26.2% |

然后回答：**三类买卖点里，哪一类对约定最敏感？**

本书的预期是**第一类**（它依赖最长的判定链：几何层 → 中枢 → 级别 →
趋势 → 背驰），但**没有测过**——留给你。

### 第五步：冻结导出

把信号序列导出成一个**带 `config_hash` 的文件**，作为第六部分的输入。

```text
signals_<日期>_<config_hash>.csv
```

⚠️ 从这一刻起，**这份文件不许再改**。
第六部分的检验必须在这份冻结的信号上做——
中途重新生成信号等于事后改规则。

### 第六步：登记

结果登记进[出处与资料](../../sources.md)第五节。

## 验收标准

- [ ] 22 项约定全部显式配置，没有硬编码？
- [ ] `confirmed` 与 `config_hash` 两个字段都有？
- [ ] 全套自检断言通过（含"增量 == 全量"）？
- [ ] 三类数量与本书基线**方向一致**（第三类 ≫ 第一类）？
- [ ] 敏感性测试报了**位置重合率**而不只是数量？
- [ ] 信号序列已冻结导出？
- [ ] 报告里**没有**出现任何关于收益、胜率、有效性的结论？

最后一条是硬要求。**P4 的产出是识别器，不是结论。**

## 常见的坑

| 坑 | 症状 | 出处 |
|---|---|---|
| 三买索引错位 | 第三类买点数量为 **0** | 第 27 章 🅑 档第一步（本书真实踩过） |
| 用 `GG` 判三买 | 三买数量趋近 0 | 第 27 章 Q1 |
| 不限制"第一次回试" | 一个中枢反复产生三买 | 第 20 课 |
| 判不重叠用 `[ZD,ZG]` | 趋势占比飙到 95%，第一类暴增 | 第 14、15 章 |
| 不输出 `confirmed` | 实时使用时误导 | 第 11 章 11.3 节 |
| 在 P4 阶段就算收益 | 越界，且必然是未预登记的 | 第 27 章 27.5 节 |
