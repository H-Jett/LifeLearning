# 第 6 章 · 思考题参考答案

> 本册**只记「问题 + 正确答案」**，不记读者作答。想清楚再看。

<a id="q1"></a>
## Q1 · 为什么有包含关系分型就无法定义

**答**：因为**"高点的比较结果"和"低点的比较结果"会指向相反的方向**。

具体到矛盾的那两个条件：

第 1 章 1.2 节的判据是成对使用的——

- 向上：高点更高 **且** 低点更高；
- 向下：高点更低 **且** 低点更低。

现在看一对包含关系的 K 线（后一根被前一根包含）：

```text
K1: 高 12  低 8
K2: 高 11  低 9
```

- 比高点：K2 的高点更**低** → 指向"向下"；
- 比低点：K2 的低点更**高** → 指向"向上"。

两个条件互相矛盾，**哪一对判据都不满足**。于是这两根 K 线之间的方向无法判定。

而分型的定义正是建立在"相邻三根 K 线的高低点比较"上的（第 7 章），
比较不出方向，分型自然无从谈起。

> **补充一句**：按第 1 章的朴素三分类，这种"高更低、低更高"的组合会被归为
> **盘整（收敛）**——这在"两段走势"的层面是合理的分类。
> 但在"两根 K 线"这个最底层，我们要的不是分类，而是**一个明确的方向**，
> 好继续往上搭分型。所以这里必须把它消掉，而不是给它一个类别。

<a id="q2"></a>
## Q2 ·【标签】"处理后不含包含关系"属于哪一类

**答**：〔推论〕。**测出残留就改代码，不改理论。**

**判别**：它能从包含处理的定义直接推出来——
滚动合并的终止条件就是"不再构成包含"，
所以只要算法跑完，输出必然不含包含关系。这一步不需要任何数据。

**为什么失败时该怀疑代码**（第 3 章 Q3 的纪律）：

一条从定义推出来的结论，**不可能被数据推翻**。
数据上出现反例，只能说明代码没有正确实现定义。

**具体排查顺序**（残留 3 个包含关系时）：

1. **合并后没有重新参与比较**。最常见的 bug：合并出新 K 线后，
   只和"原序列的下一根"比，而没有让**新合成的这根**继续和后续比较。
   滚动合并必须是"合并结果继续参与下一轮"。
2. **只处理了一种包含方向**。如果实现里只判了"前包含后"，
   那"后包含前"的情形会原样留下（见 6.4 节约定 2）。
   ⚠️ 注意：这种情况下"残留"是**约定选择的结果**，不是 bug——
   但那样就不该声称"输出无包含关系"，而应该声称"输出无前包含后关系"。
3. **相等边界没处理**（约定 4）。高点或低点恰好相等时算不算包含？
   不判会漏掉一批。
4. **浮点比较**。价格用浮点存储时，`>=` 的边界可能因精度问题判错。
   价格数据应当用定点（分）或做容差比较。

> **顺带说明本章实测的作用**：6.5 节测出"7 个样本残留全部为 0"，
> 这**不是**在验证理论正确，而是在**验证我的代码写对了**。
> 这是几何层实现的第一道自检，也是为什么这条断言值得写成测试。

<a id="q3"></a>
## Q3 · 影响这么小，为什么还要写进约定清单

**答**：至少三条理由，任答两条即可。

**理由一：可复现不是概率问题，是二值问题。**

第 4 章 4.1 节对可复现的定义是"同样的参数得到**逐行相同**的序列"。
7 个样本里有 1 个不同——这已经**违反**了定义。
"只差 1 根"在统计上很小，但在"能不能逐行对上"这个问题上，
差 1 根和差 100 根是同一件事：**对不上**。

**理由二：本章的实测结论有明确的适用条件，换条件就不成立。**

6.5 节那个结论是在**日线 + 十年长度**上测的。
初始方向的影响集中在**序列开头**，所以：

- 样本越短，开头那一段占总长的比例越大；
- 频率越低（比如周线、月线），总根数越少，开头占比同样变大。

在 5 分钟线上取一个月，或者在周线上取两年，结论可能完全不同。
一个只在特定样本条件下成立的"影响很小"，不能当成普遍豁免。

**理由三：几何层的误差会级联放大。**

包含处理的输出是分型的输入，分型是笔的输入，笔是线段的输入，
线段是中枢的输入。开头差 1 根 K 线，可能导致：

- 第一个分型的位置偏移 →
- 第一笔的起点不同 →
- 整个笔序列的**奇偶性**改变（向上笔变成向下笔）→
- 线段划分完全不同。

而中枢判定是布尔的（第 4 章 Q4）——**不存在"误差 1 根"这种中间状态**。

**理由四（加分）：约定清单的价值不在每一项都重要，而在它是完整的。**

一份写了 4 项的清单，读者可以逐项核对；
一份"重要的写了、不重要的省了"的清单，读者无法知道省掉了什么，
也就无法判断差异是从哪来的。**完整性本身就是它的功能。**

<a id="q4"></a>
## Q4 ·【判读】在原始图上数 K 线根数

**答**：他在**未合并**的序列上做了一个**只在合并后序列上才有定义**的计数。

**推理链**：

1. **看到什么**：他在原始日线图上数出 7 根 K 线，据此判断满足成笔要求。
2. **错在哪**：成笔条件里的"至少几根 K 线"，指的是**包含处理之后**的 K 线数
   （第 8 章会给出精确表述）。原始序列里有大量 K 线会被合并掉，
   它们在几何层里**不作为独立的一根存在**。
3. **偏离多少**：本章实测，日线上的合并率是 21.7%~28.6%，合计 **24.9%**。
   按四分之一估算：

   > 原始 7 根 → 合并后期望约 **5 根左右**。

   如果成笔要求是"中间至少 3 根"或"至少 5 根"这类门槛，
   **他很可能把一个不成笔的结构判成了成笔**。
4. **为什么这个错误特别隐蔽**：合并率是个平均数，**局部波动很大**。
   震荡区间里包含关系密集，可能连续合并掉一半以上；
   单边快速段里几乎不合并。所以他不能简单地"把数出来的根数乘以 0.75"补救——
   **必须真的做一遍包含处理**。
5. **正确做法**：先在这一段上做包含处理，得到合并后的高低点序列，
   **在那个序列上**数根数。

> **一般化**：几何层里凡是出现"根数""第几根"的地方，
> 都必须先确认是在**哪个序列**上数的。原始序列和合并后序列差了约四分之一。

<a id="q5"></a>
## Q5 ·【判读】整段固定用一个方向处理

**答**：会在**逆方向的走势段里系统性地把 K 线朝错误的方向合并**，
使合并后的序列失真，且失真是**有偏的**（不是随机误差）。

**推理链**：

1. **6.2 节那张表在做什么**：向上处理是 `H=max, L=max`（高低点一起抬高），
   向下处理是 `H=min, L=min`（一起压低）。
   这个设计的含义是：**合并时保留沿当前走势方向的那个极值**——
   上涨途中的一次包含，应该被理解为"上涨过程中的一次停顿"，所以取高。
2. **整段固定向上会怎样**：在一段下跌里遇到包含关系，
   他仍然执行 `H=max, L=max`，把合并后的 K 线**抬高**。
3. **后果一：低点被系统性抬高**。下跌段里本该保留的低点被 `max` 换成了较高的那个。
   于是底分型的位置、深度全都偏移——**而底分型正是一笔的端点**。
4. **后果二：误差有方向**。如果这是随机误差，长样本上会互相抵消；
   但这个误差在**所有下跌段里都朝同一个方向偏**，累积而不抵消。
   结果是整套分解在上涨段和下跌段之间**不对称**——
   而缠论的判据（中枢的重叠、趋势的方向）是对称的，
   用一套不对称的输入去喂对称的判据，结论没有意义。
5. **后果三：他的"确定性"是假的**。他想要的是"结果唯一"，
   而 6.3 节的滚动方向更新**本来就是确定的**——
   给定初始方向，后面每一步的方向都由数据唯一决定，没有任何随意性。
   他牺牲了正确性，换来的是他本来就已经有的确定性。

**正确做法**：保留滚动更新（6.3 节），
只把**初始方向**作为一个显式约定，并写进约定清单。

## Q6 ·【查证】两份实现各自选了什么

**答**：本题没有唯一答案，重点是**你真的去读了代码 / 教程并逐项对照**。

**合格答案必须包含**：

1. 两份实现的**出处**（仓库、文章、工具名，给出可查的标识）；
2. 按 6.4 节的四项约定**逐项填表**：

   | 约定 | 实现甲 | 实现乙 |
   |---|---|---|
   | 初始方向 | | |
   | 是否处理"后包含前" | | |
   | 合并后如何记时间 | | |
   | 相等边界怎么算 | | |

3. 明确回答最后一问：**有没有哪一份把自己的选择写出来了**。

**你多半会观察到的现象**（这正是本题的目的）：

- **绝大多数实现不会声明这些约定**。它们在代码里做了选择，
  但文档、注释、教程正文里只字不提。
- 于是使用者**无法知道**自己的分解结果为什么和别人不同，
  只能归因于"缠论本来就有多义性"——但这里的不同**不是**多义性
  （第 31 章会讲真正的多义性），而是**约定不同**。
- 有些实现甚至**在同一份代码里不一致**：比如某个函数处理两种包含，
  另一个辅助函数只处理一种。

**加分项**：

- 找到一份**明确声明了约定**的实现，并指出它是怎么声明的
  （配置项？文档表格？注释？）；
- 把两份实现跑在同一段数据上，统计合并后序列的**长度差**——
  这是把"约定不同"从定性变成定量；
- 注意到第 2 项约定（是否处理"后包含前"）的分歧最大，
  这与本章 6.4 节的说法一致。

**典型不合格答案**：

- 只写"两份实现不一样" → 没有定位到**哪一项**约定不同。
- 断言其中一份"错了" → 除非它自相矛盾，否则**两者都不算错**，
  只是选了不同的约定。本章的立场是"标准统一优先于标准正确"（第 11 章会展开）。
