# 第 4 章 · 思考题参考答案

> 本册**只记「问题 + 正确答案」**，不记读者作答。想清楚再看。

<a id="q1"></a>
## Q1 · 既然消跳空效果一样，为什么非要后复权

**答**：因为两者解决的是**不同的问题**。消跳空解决的是"数据对不对"，
后复权解决的是"数据**稳不稳**"。

机制上讲清楚：

**前复权怎么算的**：以**最新价**为基准，把历史价格按累计复权因子向前缩放。
关键在于"最新价"这个基准——它是**活的**。

**于是会发生什么**：

1. 今天你取了一段前复权历史，某日收盘价是 X；
2. 三个月后该标的又分红一次，累计复权因子变了；
3. 你**用完全相同的参数**再取一次同一段历史，该日收盘价变成了 X′ ≠ X。

也就是说：**前复权序列不满足第 4.1 节对"可复现"的定义**——
同样的取数参数，不同时间执行，得到的序列不同。

后复权以上市初期为基准向后缩放，基准是**死的**，
所以同一个历史日期的价格今天取和三年后取完全一样。

**为什么这件事对缠论特别要命**（第 2 章 Q4 讲过，这里补一句更根本的）：

缠论的核心判据是 `ZD ≤ ZG` 这样的**区间重叠判断**——
它是一个**布尔判定**，不是一个连续量。连续量的微小变化只带来微小误差；
布尔判定的微小变化会**直接翻转结论**，然后沿着
中枢 → 走势类型 → 级别 → 背驰 这条链**级联**下去。

所以：

> 一个会随时间悄悄改变历史的数据序列，加上一套对价格敏感的布尔判据，
> 结果是**你今天的结论没办法被任何人（包括未来的你自己）复核**。

**补充**：如果确实想用前复权（看盘习惯、或者要用真实价位做成本估算），
合规做法是**存下一份带日期戳的快照**，之后所有分析都读这份快照。
关键不是"哪种复权更对"，而是**分析读的那份数据必须是冻结的**。

## Q2 ·【判读】"拿不到数据所以库不能用"

**答**：他把一个**三元组的属性**当成了**数据源自己的属性**。

**推理链**：

1. **看到什么**：在他的环境里，某个库的接口报错。
2. **他推出了什么**：这个库不能用。
3. **错在哪**：按本章 4.3 节，"能不能拿到数据"取决于
   **你的网络出口 × 上游站点当前策略 × 库版本** 这个三元组，
   而不是库本身。爬虫型数据源尤其如此——它去抓的是第三方站点，
   上游改版、限流、按来源封禁，接口就失效，**和库的代码质量无关**。
4. **本章就是活例子**：同一台机器上，某个爬虫型库四个接口全部连接被中断，
   而另一个有自有服务端的库全部通畅。换一台机器，结论完全可能反过来。

**他还需要补充什么**（缺一不可）：

- **测试日期**：上游策略随时变；
- **网络环境**：出口在哪、是否有代理；
- **库版本**：接口失效后社区常会修，旧版本的失败不代表新版本；
- **具体错误类型**：是连接被中断、超时、返回空体，还是解析失败？
  这四种指向完全不同的原因；
- **至少换一个环境复测一次**：这是区分"数据源问题"和"我的环境问题"的唯一办法。

**正确的表述**：
"在 ⟨日期⟩、⟨环境⟩、⟨版本⟩ 下，该库的 ⟨这几个⟩ 接口返回 ⟨这个错误⟩；
在同一环境下另一个库可用。因此**在这个环境里**我选用后者。"

注意最后一句——结论应该是"我在这里选谁"，而不是"谁更好"。

<a id="q3"></a>
## Q3 ·【标签】"未复权的危害不在多，在极端"

**答**：〔推论〕——但它是一个**由定义加实测数据共同支撑**的推论，
值得说清楚这个混合结构。

**判别过程**：

1. 它在规定词义吗？不是。
2. 能从定义推出来吗？**能，推出一半**：
   从中枢的定义可以直接推出"中枢是否成立取决于三段区间有无共同重叠"，
   而重叠与否是**布尔判定**。布尔判定对**极端值**敏感、对**频率**不敏感——
   这一步纯粹是从定义来的，不需要任何数据。
3. 剩下一半需要数据：**除权跳空的幅度真的能大到撕裂中枢吗**？
   这要测。

**本章怎么支持它的**：

| 支撑 | 来自哪 |
|---|---|
| "中枢判定是布尔的，怕极端不怕频率" | 中枢的定义（纯推导） |
| "除权跳幅实测最高 67.3%，另有 45.9% / 47.3% / 50.3%" | 4.4 节实测 |
| "未复权只虚增约 0.17% 的大跳变" | 4.4 节实测 |

三者合起来才构成完整论证：**频率低（0.17%）+ 幅度极大（最高 67.3%）
+ 判据对极端敏感（定义）→ 危害被频率严重低估**。

**为什么不标〔经验断言〕**：因为它的核心逻辑（布尔判据怕极端值）
是从定义推出来的，数据只是**标定了极端值有多极端**。
如果换一批样本测出最大跳幅只有 3%，这条推论的**形式**依然成立，
只是在那批样本上后果没那么严重。

> 这是一个很好的例子，说明四个标签不是互斥的抽屉，
> 而是**"这句话靠什么站住"** 的说明。
> 遇到混合结构时，把各部分分别标出来比硬塞进一个标签更有用。

<a id="q4"></a>
## Q4 · "误差只有 0.2%，无所谓"错在哪

**答**：他把一个**结构性判据**当成了**统计性指标**。

**推理链**：

1. **他的推理**：坏数据占 0.17% → 结论的误差大约也是 0.17% → 可以忽略。
   这个推理在"求平均值""算收益率"这类**统计量**上是对的——
   0.17% 的污染确实只带来 0.17% 量级的偏差。
2. **为什么在这里不成立**：中枢的判定不是求平均，是判断

   ```text
   ZD = max(a2, b2, c2)   ZG = min(a1, b1, c1)
   构成中枢  ⟺  ZD ≤ ZG
   ```

   这是一个**布尔判定**。它的输出只有"成立/不成立"两个值，
   **没有"误差 0.17%"这种中间状态**。

3. **一次污染会发生什么**：
   假设三段中有一段的高低点被一次 67% 的假跳空改写。
   那么 `max` 或 `min` 的取值被彻底改变，
   `ZD ≤ ZG` 可能从成立翻转为不成立——**这个中枢凭空消失了**。
4. **然后级联**：
   - 中枢消失 → 该段的中枢计数少了一个 → 本该是"趋势"的被判成"盘整"
     （或反过来）；
   - 走势类型错 → **级别**错（级别由中枢递归构造）；
   - 级别错 → 背驰的前提"两中枢同级别"失效 → 背驰判定连带作废；
   - 买卖点建立在背驰上 → 全错。

   一个坏数据点，毁掉的不是 0.17% 的结论，而是**包含它的那整条分解链**。

5. **正确的评估方式**：不要问"坏数据占多少"，
   要问"**有没有一个坏数据点落在我关心的那几段里**"。
   答案是有或没有，不是百分之几。

> **一般化**：凡是判据里出现 `max`、`min`、阈值比较、布尔判定的地方，
> 都要按"最坏情况"评估数据质量，而不是按"平均情况"。
> 缠论几乎处处是这种判据。

## Q5 ·【判读】"5 分钟级别过去十年的表现"

**答**：他会撞上一堵**数据墙**——不是方法问题，是数据根本不存在。

**推理链**：

1. **看到什么**：他要的是 5 分钟频率、十年跨度。
2. **本章实测说了什么**：在本书的测试环境下，该数据源的 5 分钟线
   **最早只到 2020 年初**（本次取到 77568 行）。
   也就是说"过去十年"里，有相当一部分**压根拿不到**。
3. **他可能怎么出错**（这一步最关键）：
   如果他不检查历史深度，直接按"起始日期 = 十年前"去取，
   接口通常**不会报错**，而是**静默地返回它有的那部分**。
   于是他以为自己在十年样本上做检验，实际上只在近几年的样本上做——
   而且他**不知道**。这比报错危险得多。
4. **还会连带什么问题**：
   - 近几年的样本可能刚好覆盖某一种市场状态，结论不可外推；
   - 样本量比他以为的小，统计显著性被高估；
   - 如果他还在多个频率之间对比，**各频率的可用区间不一样**，对比就不公平。

**应该怎么调整研究设计**（合格答案至少给出前三条）：

1. **先测历史深度，再定研究区间**。把"数据可用区间"当成一个**硬约束**
   写进[检验预登记表](../forms/prereg-template.md)，而不是事后发现。
2. **把研究区间缩到数据真正覆盖的范围**，并在结论里明写这个范围。
   "过去十年"改成"⟨实际起止日期⟩"。
3. **多频率对比时，统一到各频率都覆盖的公共区间**，否则对比不成立。
4. **检查取回的数据行数是否符合预期**（交易日数 × 每日根数），
   不符合就说明被静默截断了——这正是第 4.5 节体检清单里那条
   "每日 K 线根数是否恒定"要拦的。
5. **如果结论必须建立在十年样本上**，那就换到日线频率做，
   或者接受"这个问题在当前可得数据下答不了"——
   后者是一个**完全正当的结论**，比硬做一个自己都不知道样本被截断的检验强得多。

## Q6 ·【查证】你自己的实测报告

**答**：本题没有唯一答案。**得到和本章不同的结果，才是这道题的正常结局。**

**合格答案必须包含**：

1. **完整的记录**：测试日期、网络环境（出口大致位置、是否有代理）、
   各库的版本号、每个接口的结果（成功则给行数与起止日期，失败则给**具体错误类型**）。
2. **与本章表格的逐项对照**，明确指出哪些一致、哪些不一致。

**最后一问的答案**：

本章 4.2 节那张表应该被当成——

> **一次带时间戳与环境标注的观测记录，不是关于数据源的事实。**

理由就是 4.3 节那条推论：数据可得性是
"网络出口 × 上游策略 × 库版本"这个三元组的属性。
本章自己就演示了这一点：同一台机器上，一个库全通、另一个库四个接口全断。

**加分项**（想到任何一条都说明理解到位）：

- 意识到**本书也在接受同样的检验**：如果你的实测和本章冲突，
  本章那张表并没有"错"，它只是在另一个环境里不成立——
  而这恰恰是本章要教的。
- 意识到这条原则**可以推广**：任何"我测过，结论是 X"的说法，
  都应该带着测量条件读。第六部分讲检验时，这会变成一条更强的纪律
  （样本范围、参数、成本假设全部要写明）。
- 意识到**失败也要记录**。很多人只记录成功的那个源，
  于是半年后接口失效时，完全不知道当初试过什么、为什么没选另一个。

**典型不合格答案**：

- 只写"我也试了，baostock 能用" → 没有日期、没有环境、没有版本，
  和本章批评的那些对比文章是一回事。
- 结果不一致就下结论"本章写错了" → 理解偏了。
  在没有给出环境差异分析之前，"不一致"本身就是本章论点的**证据**，不是反例。
